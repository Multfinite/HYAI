# Архитектура домена `docs`

## Корпус документов

| Каталог | Что | Уровень по умолчанию |
| --- | --- | --- |
| `specs/<система>/tz.md` | техническое задание | `normative` |
| `specs/<система>/` | технические спецификации подсистем | `normative` |
| `docs/` | руководства, README, справочники | `descriptive` |
| `diagrams/` | текстовые схемы | `illustrative` |

## Инварианты

| ID | Инвариант | Чем проверяется |
| --- | --- | --- |
| `DOC-INV-01` | Требование без критерия приёмки не является требованием (`DOC-POL-02`) | ревью + `lint_terms.py --domain docs` |
| `DOC-INV-02` | Документ не описывает несуществующее поведение (`DOC-POL-03`) | `docs/analysis` + расхождение как `Q-*` |
| `DOC-INV-03` | Схема хранится текстом (`DOC-POL-10`) | правило `doc.diagram-as-image-only` |
| `DOC-INV-04` | Ссылки на код с путём и строкой (`DOC-POL-08`) | `check_links.py` |

## Анти-паттерны

| Не делаем | Почему | Что вместо |
| --- | --- | --- |
| «Полное руководство по всему» (`DOC-POL-09`) | Устаревает целиком, не ревьюируется | Один документ — одна тема и один читатель |
| ТЗ как пересказ решения | Смешивает «что» и «как» | Требование — в ТЗ, выбор — в решении |
| Диаграмма картинкой | Не диффится, расходится с кодом | Mermaid/PlantUML в тексте |
| Комментарий вместо документа (`DOC-POL-14`) | Комментарий не источник истины | Ссылка на документ |
