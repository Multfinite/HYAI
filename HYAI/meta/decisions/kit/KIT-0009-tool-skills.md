# KIT-0009. Навыки внешних инструментов: по серверу и по пространству данных

## Решение

Каталог навыков получает третий класс — навыки внешних инструментов (MCP). Он делится по двум
разным вопросам, и это деление обязательно:

1. **Серверный навык** (`hyai-mcp-<server>`) отвечает «как пользоваться этим сервером»: что даёт,
   когда брать, порядок вызовов, ловушки, поведение без него. Он не знает о других серверах.
2. **Комбинационный навык** (`hyai-mcp-<data-domain>`) отвечает «где правда и кто пишет, когда
   серверов несколько»: иерархия источников, порядок чтения и записи, ключи проекта, что меняется
   от добавления второго хранилища.

Роутер `hyai-mcp` описывает только доступность и выбор: наличие инструмента проверяется по
фактическому списку в сессии, а не по тексту навыка.

Источники — `HYAI/core/shared/skills/<name>/SKILL.md`, копируются в `.github/skills/` сборщиком
[`build_skills.py`](../../../tools/build_skills.py). Данные для них не генерируются: знание о внешнем
сервере не выводится из профилей проекта (`3D` здесь не применим — это не предметная область
проекта, а описание чужого инструмента).

**Установочные данные в навыки не попадают:** адреса, ключи, порты, имена инстансов, порядок
регистрации. Их даёт пользователь. Проверяется тестом, который ищет такие маркеры в собранном
каталоге.

**Внешние ссылки в навыки не попадают:** адрес документации устаревает молча, а непроверенная
ссылка выглядит как подтверждение. Вместо ссылки навык задаёт метод: точное поведение сервера —
его репозиторий и журнал изменений, вопрос про библиотеку — документация по версии; источник
ищется в момент вопроса. Протокол MCP (транспорт, сессии, авторизация) — зона клиента, поэтому в
навыках описан только минимум, меняющий поведение агента: инструменты, ресурсы, промпты и порядок
диагностики «инструмента нет».

## Почему

Смешение двух вопросов в одном навыке делает его непригодным: «как вызвать» меняется вместе с
версией сервера, а «где истина» — вместе с составом подключённых серверов. Один текст не может
отвечать обоим требованиям, не устаревая.

Отдельно важно, что добавление второго сервера меняет **распределение данных**, а не только
набор доступных вызовов: два хранилища памяти дают два ответа, индекс отстаёт от источника, факты
получают время действия. Без комбинационного слоя агент пишет в первое попавшееся хранилище и
теряет источник.

## Последствия

- Каталог растёт: 27 серверных навыков, 6 комбинационных, 1 роутер; `description` серверного
  навыка называет сервер и задачу, а не «MCP» вообще, иначе навыки конкурируют за активацию.
- `check_indexes.py` не требует README внутри авторских навыков: навигацию задаёт frontmatter,
  а не оглавление каталога.
- Поставка остаётся единой: один сборщик, одна проверка дрейфа, один CI-шаг.
- Новый сервер — это один файл в `shared/skills/`; новый комбинационный навык нужен, только если
  сервер делит данные с существующими.
