# KIT-0008. Навыки Agent Skills как генерируемая проекция доменов и профилей

## Решение

Каркас поставляет каталог навыков Agent Skills (`.github/skills/`) как **генерируемую проекцию**
активных доменов и процессов. Источник правил не переезжает: `AGENTS.md`, `policy.md`,
`access.md`, `profile.yaml` и проверки остаются единственным местом, где норма живёт.

Три уровня каталога:

- `hyai` — определяет домен и профиль, объявляет активные домены и маршрут чтения;
- `hyai-<domain>` — профили домена, классы правил, проверки, реестр «читать первым»;
- `hyai-<domain>-<procedure>` — процесс с собственным триггером `when_to_use` в frontmatter.

Навык **не разрешает и не запрещает**: `PERM-N`, ворота `G0..G3`, `STOP-*`, контуры доступа и
`require_approval_for` действуют из файлов. Удаление каталога навыков не меняет ни одного
правила — оно только замедляет вход. Запрет, выведенный из текста навыка, остаётся нарушением
`HYAI-PERM-N10`.

Сборка — `HYAI/tools/build_skills.py`: `--check` сравнивает каталог со сборкой (`rc=1` при
дрейфе), `--write` пишет и удаляет устаревшие навыки по маркеру. Нет данных — `rc=2`, а не
тихий пропуск. Имён доменов в коде нет (`3D`): всё читается из `active`, доменных манифестов,
`profile.yaml` и заголовков политики.

## Почему

Вход агента был одним always-on файлом: право, навигация и краткое содержание доменов в одном
`AGENTS.md`. Активация начиналась только после чтения таблицы профилей, а оболочки, не читающие
`AGENTS.md`, не получали навигации вовсе.

Agent Skills добавляют ровно один новый носитель — `description`, по которому хост сопоставляет
задачу с ситуацией. Отдать ему право нельзя: инвариант не должен зависеть от того, загрузит ли
модель файл. Поэтому право остаётся always-on, а навык получает активацию и ссылки.

Копии политики в навык не переносятся: `picture/policy.md` — 85 КБ, копия разошлась бы с
источником. Вместо этого навык домена содержит классы правил и индекс идентификаторов, а полный
текст читается по ссылке.

## Последствия

- Каталог навыков версионируется и проверяется на дрейф в `validation.assemble` и в CI, как
  `AGENTS.md`.
- Схема frontmatter исключает `.github/skills` из проверки документов: `SKILL.md` — вход
  агентской оболочки, а не документ HYAI; поля `id/title/visibility` ему не принадлежат.
- Формулировки навыков живут в `HYAI/core/shared/templates/skill-*.md` — это форма, а не норма,
  поэтому уточняются без решения `KIT-*`.
- Процесс попадает в каталог только при наличии `when_to_use`; добавление триггера — правка
  домена, а не каркаса.
- Сокращение `AGENTS.md` этим решением не выполняется: навигация дублируется намеренно, пока
  новый вход не проверен на живых задачах. Отдельное решение должно снять дубль.
