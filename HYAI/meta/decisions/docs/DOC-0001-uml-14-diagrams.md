# DOC-0001. Регламент UML 2.5 из 14 диаграмм

## Решение

Домен `docs` признаёт закрытый список из 14 типов диаграмм UML 2.5 как единственную основу
для UML-схем: общие правила `DOC-POL-16..20` и по одному правилу типа `DOC-POL-21..34`.
По каждому типу существует процесс `docs/uml-*` с триггером `when_to_use`, из которого
собирается навык `hyai-docs-uml-*`. Общая активация по вопросу, когда тип не назван,
осуществляется авторским навыком `uml`.

## Почему

До решения в домене были только общие правила `DOC-POL-10..12` и один процесс `docs/diagrams`:
тип выбирался «по привычке», а активации по конкретной диаграмме не было. Запрос владельца —
иметь инструкции и регламент по всем 14 типам и навык на каждый плюс общую активацию UML.

## Границы

- Решение не вводит новый домен, профиль или класс правил: защищённые зоны не тронуты.
- ER, C4 и BPMN не объявляются UML-типами; подмена возможна только решением `DOC-*`.
- Навыки — генерируемая проекция процессов и авторская копия, а не источник нормы.
- Новые правила добавлены по запросу владельца; формулировки остаются в `status: approved`,
  пока владелец не подтвердит финальную редакцию (`HYAI-PERM-N05`).

## Открытые вопросы

- `Q-DOC-01` — требуется ли поднять новые правила до `approved` после ревью владельца?

## Последствия

- Процесс и схема проверяются по одному каркасу из девяти шагов в `uml.md`.
- Проверка соблюдения: `python3 HYAI/tools/run_checks.py` и `python3 HYAI/tools/check_rules.py`.
