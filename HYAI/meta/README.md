# `HYAI/meta/` — шаблон данных проекта

Это **шаблон**: его копируют в `./meta` нового проекта и правят под себя. `HYAI/meta/` в
репозитории каркаса — образец, из которого проект создаёт собственные данные; данные
конкретного проекта живут в его корне `./meta`, а не в каталоге каркаса.

`HYAI/core/` можно обновлять из общего репозитория, не задевая `meta/` и `tools/` проекта:
инструкции отдельно, данные и движки проекта отдельно.

## Состав

| Путь | Что | Общее или доменное |
| --- | --- | --- |
| [`manifest.yaml`](manifest.yaml) | Активные домены и профили, пути, проверки | Проект |
| [`project.md`](project.md) | Идентичность проекта, стек, карта репозитория | Проект |
| [`architecture.md`](architecture.md) | Хаб: границы доменов и ссылки | Проект, без норм |
| [`architecture/`](architecture/README.md) | Устройство каждого домена | Домен |
| [`terminology.md`](terminology.md) | Кросс-доменные термины | Проект |
| [`terminology/`](terminology/README.md) | Словари доменов | Домен |
| [`questions.md`](questions.md) | Проектные вопросы `Q-P-*` | Проект |
| [`questions/`](questions/README.md) | Вопросы доменов | Домен |
| [`decisions/`](decisions/README.md) | Решения по областям | Строго по области |
| [`schema/`](schema/README.md) | Базовая схема frontmatter и оверлеи доменов | Проект + домен |
| [`lint/`](lint/README.md) | Правила ссылок, пробелов, терминов | Проект + домен |
| [`registry/`](registry/README.md) | Что читать первым | Проект |
| [`reports/`](reports/README.md) | Отчёты по областям, планы, архив | Домен |

## Правила

1. Каталог описывает ровно то, что в нём лежит (`HYAI-ART-09`): доменный файл не повторяет проектный.
2. У каждого факта есть маркер провенанса (`HYAI-PROV-01`).
3. Место решения определяется его областью, а не удобством автора (`HYAI-DEC-01`, `HYAI-DEC-02`).
