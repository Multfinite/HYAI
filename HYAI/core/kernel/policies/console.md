# CLI — консольный интерфейс по умолчанию

Норма для любой консоли, которую поставляет компонент: эмулятор, фасад, служба. Домен и проект её не переписывают — они применяют её к своим командам и добавляют только имена, которых здесь нет.

Один флаг — одно правило. Ниже — только обязательства; критерии приёмки и скелет реализации живут там, где норма применяется.

## 1. Границы

`HYAI-CLI-01`. Норма обязательна для каждой консоли с корневой точкой входа (`startup.py` или её аналог). Компонент без консоли ей не подчиняется.
`HYAI-CLI-02`. Норма задаёт внешний контракт: имена, синтаксис, вывод, коды возврата, автозапуск, структуру каталогов. Внутреннее устройство команд она не ограничивает.
`HYAI-CLI-03`. Интерфейс командной строки и шина команд по JSON (действия вида `scan`, `read`, `write`) — разные контракты. Норма распространяется только на командную строку.

## 2. Синтаксис

`HYAI-CLI-04`. Флаг пишется с двумя ведущими дефисами. Флаг — это вызов: команда (`--up`, `--status`, `--register-service`) или переключатель (`--detach`, `--help`, `--json`).
`HYAI-CLI-05`. Аргумент флага пишется с одним ведущим дефисом и берёт значение следующим словом: `--read-file -encoding utf-8 -path config.yaml`.
`HYAI-CLI-06`. Значение флага, которому оно нужно, идёт следующим словом без дефиса: `--mqtt-port 1883`, `--file runtime/report.md`.
`HYAI-CLI-07`. Внутри флага пробела нет. Дефис, стоящий не в начале слова, — часть имени: `--read-file` и `--mqtt-port` — каждый один флаг, а не два.
`HYAI-CLI-08`. Знак `=` не используется. Повтор флага в одном вызове — ошибка использования.
`HYAI-CLI-09`. Позиционных аргументов нет: всё, что не начинается с дефиса, — значение предыдущего флага или аргумента.

## 3. Команды

`HYAI-CLI-10`. Обязательные имена: `--up`, `--down`, `--logs`, `--build`, `--rebuild`, `--clear`, `--report`, `--doctor`, `--plan`, `--status`, `--endpoints`, `--ports`, `--journal`, `--register-service`, `--unregister-service`, `--help`, `--commands`. Имя вне набора вводится только решением владельца каркаса.
`HYAI-CLI-11`. `--compile` и `--recompile` объявляются только там, где у сборки есть отдельный этап компиляции. Их отсутствие у компонента без такого этапа — не нарушение.
`HYAI-CLI-12`. Одно имя несёт один смысл во всех компонентах: `--status` ничего не поднимает, `--plan` не имеет побочных эффектов, `--clear` не останавливает процессы.
`HYAI-CLI-13`. `--clear` удаляет мусор: временные файлы, журналы, логи, артефакты сборки. Подтверждения не требует. Состояние стенда не трогает — его снимает `--down`. При живом стенде отказывается (код `3`): журнал работающего прогона мусором не является.
`HYAI-CLI-14`. `--logs` показывает сырой вывод процессов, `--journal` — записи журнала событий. Одна команда не подменяет другую.
`HYAI-CLI-15`. `--endpoints` отвечает на вопрос «какие конечные точки объявлены и доступны», `--ports` — «что слушает на каком порту». Совпадение наборов не делает команды взаимозаменяемыми.
`HYAI-CLI-16`. `--commands` печатает машинный список команд: имя, назначение, флаги, аргументы, наличие `--json`, признак интерактивности. Это единственный источник для `--help` и автодополнения.
`HYAI-CLI-17`. `--help` — человеческая справка. `--json` к нему не применяется.

## 4. Служебные флаги

`HYAI-CLI-18`. Порт и адрес службы задаются парой `--<служба>-port` и `--<служба>-host`: `--mqtt-port`, `--mqtt-host`, `--core-host`. Разделитель — дефис; подчёркивание не используется нигде.
`HYAI-CLI-19`. `--whois-port`, `--whois-host`, `--whois-service`, `--whois-process` сообщают, какая подсистема и какой процесс запустили это приложение.
`HYAI-CLI-20`. `--whois-host` принимает либо адрес, либо имя подслужбы: на адрес отвечает именем службы, на имя — адресом. Ответ — одна строка в человеческом режиме и объект `{service, host, port, process}` в машинном.
`HYAI-CLI-21`. Сквозной набор флагов одинаков во всех командах, где они применимы: `--json`, `--help`, `--lang`, `--dry-run`, `--file`, `--dir`, `--name`, `--timeout`. Команда может их игнорировать, но не может переопределять их смысл.

## 5. Вывод

`HYAI-CLI-22`. Консоль работает в UTF-8: до первого вывода `stdout` и `stderr` переводятся в `utf-8` с `errors="replace"`. Падение команды из-за кодировки консоли — дефект, а не ограничение платформы.
`HYAI-CLI-23`. Результат команды идёт в `stdout`, диагностика и ошибки — в `stderr`. Смешивать потоки нельзя: перенаправление `stdout` в файл не должно терять ошибки.
`HYAI-CLI-24`. В человеческом режиме смысл несут маркеры `✓`, `✗`, `!`, `·`, `→`; цвет не используется. Если поток не может передать маркер, печатается ASCII-замена: `[ok]`, `[fail]`, `[!]`, `[.]`, `->`.
`HYAI-CLI-25`. В машинном режиме `stdout` содержит ровно один JSON-объект и ничего больше. Обязательные поля: `ok` (bool), `command` (string), `version` (string), `lang` (string), `data` (object); при отказе добавляется `errors`. Исключение по форме одно — `--logs`: NDJSON, по объекту на строку.
`HYAI-CLI-26`. Машинный вывод не переводится: ключи и значения-идентификаторы английские при любом `--lang`. Переводится только человеческий текст.
`HYAI-CLI-27`. Коды возврата одинаковы в обоих режимах: `--json` меняет форму вывода, но не смысл результата.

## 6. Коды возврата

`HYAI-CLI-28`. Реестр: `0` успех; `1` проверка не прошла; `2` ошибка использования; `3` предусловие не выполнено; `4` внешняя зависимость не отвечает; `5` операция запрещена; `124` таймаут; `130` Ctrl+C; `143` SIGTERM.
`HYAI-CLI-29`. Диапазон `1..99` принадлежит реестру. Произвольный код в этом диапазоне запрещён: новый смысл добавляется в эту политику, а не в код команды.
`HYAI-CLI-30`. Ошибка конфигурации — ошибка использования (код `2`), а не «проверка не прошла» (код `1`). Расшифровка реестра обязательна в `CLI/README.md` и `CLI/AGENTS.md` компонента.

## 7. Жизненный цикл

`HYAI-CLI-31`. `--up` блокирует консоль: стенд живёт, пока команда не завершится, `Ctrl+C` гасит процессы и снимает состояние.
`HYAI-CLI-32`. `--detach` отвязывает стенд от консоли: команда выходит с кодом `0`, процессы остаются. Живого вывода у отвязанного стенда нет, `--logs` читает файлы.
`HYAI-CLI-33`. Повторный `--up` при живом стенде завершается кодом `3` и указывает на `--down`, а не поднимает второй экземпляр.

## 8. Кроссплатформенность

`HYAI-CLI-34`. Автозапуск: Linux — `systemd`, Windows — Планировщик задач. Другие платформы вне обязательного контура: `launchd` и подобные системы вводятся только тогда, когда компонент действительно поставляется на эту платформу.
`HYAI-CLI-35`. По умолчанию служба регистрируется в контуре текущего пользователя: `systemctl --user` на Linux, задача с триггером «при входе» на Windows. Флаг `--system` переводит регистрацию в системный контур и требует прав администратора.
`HYAI-CLI-36`. `--register-service` и `--unregister-service` идемпотентны: повторный вызов не падает и сообщает фактическое состояние. Отсутствие прав — код `3` и готовая команда для повышения; самовольные `sudo` и UAC не применяются.
`HYAI-CLI-37`. Обе команды печатают точную команду ОС, которую выполнили. `--dry-run` печатает её и ничего не меняет.

## 9. Язык

`HYAI-CLI-38`. Язык по умолчанию — английский. Системные настройки переключают его на `ru`; неподдерживаемая или неопределённая локаль оставляет `en`. Поле `lang` в машинном выводе всегда содержит конкретный код, и этот код — `en`, пока не задано иное.
`HYAI-CLI-39`. Принудительный язык задаётся флагом `--lang <код>`. Строки живут в `CLI/locale/<код>.json`; отсутствующий ключ берётся из `en`, а отсутствие и там — дефект, который ловит `--doctor`.

## 10. Транспорт

`HYAI-CLI-40`. Порядок транспорта: `stdin`/`stdout`, затем сокет, затем именованный канал. Каждый следующий уровень применяется только при недоступности предыдущего, и выбранный уровень виден в `--status`.
`HYAI-CLI-41`. Присоединённый стенд отдаёт вывод дочерних процессов прямо в `stdout` консоли, без промежуточного канала.

## 11. Интерактив

`HYAI-CLI-42`. Запрос ввода допускается только для того, о чём пользователь попросил явно, и только для названной команды. Остальные команды неинтерактивны.
`HYAI-CLI-43`. Запрос возможен только при `stdin.isatty()` и незаданном флаге. Иначе — код `3` и подсказка с именем флага. Признак интерактивности команда объявляет в `--commands`.

## 12. Структура

`HYAI-CLI-44`. Корневая точка входа — шим: добавить корень в `sys.path`, вызвать `CLI.main`, вернуть код. Логики в нём нет.
`HYAI-CLI-45`. В `CLI/commands/` лежит по файлу на команду с контрактом `run(ctx) -> int`. `CLI/main.py` содержит разбор флагов, `--help`, `--commands` и коды возврата, но ни одного тела команды.
`HYAI-CLI-46`. `CLI/AGENTS.md` и `CLI/README.md` обязательны. Оба содержат таблицу команд и реестр кодов возврата из `HYAI-CLI-28`.
