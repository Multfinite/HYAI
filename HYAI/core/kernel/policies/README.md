# Политики ядра

Пять файлов, каждый отвечает на один вопрос. Если ответ приходится искать в двух — это дефект структуры, а не задача для читателя.

| Вопрос | Файл | Пространство ID |
| --- | --- | --- |
| Что нельзя делать никогда и что требует одобрения? | [`permissions.md`](permissions.md) | `PERM-*` |
| Насколько документ нормативен и откуда взято утверждение? | [`provenance.md`](provenance.md) | `PROV-*` |
| Какую форму имеет результат и где он лежит? | [`artifacts.md`](artifacts.md) | `ART-*` |
| Как принимаются и сливаются решения? | [`decisions.md`](decisions.md) | `DEC-*` |
| Как агент начинает работу, общается с человеком и согласует параллельное исполнение? | [`interaction.md`](interaction.md) | `INT-*` |

## Правила пространств ID

1. Префикс ID принадлежит владельцу файла: `PERM/PROV/ART/DEC/INT` — ядро, `SW-*` — домен `software`, `NR-*` — домен `narrative`, `KIT-*` — домен `kit`.
2. Профиль не вводит новый префикс. Профиль **уточняет** правило своего домена ссылкой (`SW-POL-04 применяется к миграциям как SW-POL-04.1`).
3. Текст правила не дублируется между файлами: домен либо ссылается на ядро, либо вводит своё правило со своим ID (`HYAI-PROV-03` → `NR-POL-02`).
4. Пустой профиль (нет ни одного собственного правила, ни одной проверки) не имеет права быть объявленным: `check_domains.py` вернёт `rc=1`.
