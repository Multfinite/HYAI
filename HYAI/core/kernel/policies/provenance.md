# PROV — нормативность и провенанс

Ядро задаёт **механику**: какие оси существуют, какие маркеры допустимы и как они наследуются. Ядро **не задаёт значения**: словарь уровней нормативности и список статусов объявляет домен в `schema/authority.yaml` (см. [`../spec/merge-rules.md`](../spec/merge-rules.md)).

## 1. Четыре оси документа

| Ось | Где объявлена | Смысл |
| --- | --- | --- |
| `authority` | домен: `schema/authority.yaml` | Насколько документ обязателен и что стоит его изменить |
| `status` | домен: `schema/authority.yaml` | Стадия жизненного цикла (`draft` → `review` → `approved` → …) |
| `visibility` | домен: `schema/access.yaml` | Контур доступа |
| `scope` | ядро | Принадлежность: `project` или домен |

`authority` и `status` — разные оси. Документ может быть `authority: contract` и `status: draft`: он описывает обязательство, но ещё не принят.

## 2. Алфавит маркеров (не доменный)

| Маркер | Значение | Обязательное условие |
| --- | --- | --- |
| `[А]` | Решение владельца: ADR, явное указание в задаче | Ссылка на `P-/KIT-/SW-/NR-` решение или номер сообщения |
| `[И]` | Источник в репозитории: файл, строка, спецификация | Путь и, где возможно, строка |
| `[В]` | Измерено или выведено: тест, бенчмарк, вычисление | Чем измерено и когда |
| `[Г]` | Гипотеза, не подтверждённая | Что нужно, чтобы подтвердить |
| `[?]` | Открытый вопрос | `Q-*` из `HYAI/meta/questions.md` или `HYAI/meta/questions/<domain>.md` |

`HYAI-PROV-01`. Утверждение о факте без маркера — ошибка: либо маркер, либо формулировка «не проверено».
`HYAI-PROV-02`. Маркер `[А]` без ссылки на решение — ошибка. `[?]` без `Q-ID` — ошибка.
`HYAI-PROV-03`. `[Г]` в документе со `status: approved` — ошибка: гипотеза не может быть утверждённой нормой.
`HYAI-PROV-04`. Алфавит маркеров един для всех доменов. Домен может добавить **смысл** только через `[А] -> решение домена`, но не новый символ.

## 3. Наследование

`HYAI-PROV-05`. Документ не может быть нормативнее своего источника: производный документ понижает уровень, не повышает.
`HYAI-PROV-06`. Пересказ, сводка и таблица наследуют **самый строгий** уровень нормативности среди источников.
`HYAI-PROV-07`. Понижение уровня (`contract` → `convention`) фиксируется в отчёте строкой `authority_downgrade: <причина>`; иначе считается ошибкой ревью.
`HYAI-PROV-08`. Норма живёт в одном файле (`DOC-подобное правило ядра`): повтор нормы в соседнем документе заменяется ссылкой с указанием ID правила.

## 4. Правило проверяемости

`HYAI-PROV-09`. Норма без проверки — это пожелание. Каждая политика обязана указать, чем её правило проверяется: скриптом, полем frontmatter или явной пометкой `enforced: prose-only` с причиной, почему автоматизация невозможна.
