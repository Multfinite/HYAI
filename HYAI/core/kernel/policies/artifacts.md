# ART — артефакты

## 1. Где что лежит

| Артефакт | Путь | Проверка |
| --- | --- | --- |
| Отчёт | `HYAI/meta/reports/<scope>/YYYY-MM-DD-<slug>.md` | `check_report.py` |
| План | `HYAI/meta/reports/plans/<slug>.md` | не проверяется как отчёт |
| Архив отчётов | `HYAI/meta/reports/archive/<YYYY>/` | не проверяется |
| Промежуточные файлы | `HYAI/meta/intermediate/` | вне Git, `skip_parts` |
| Выгрузки | `Exports/` | вне Git |
| Решение | `HYAI/meta/decisions/<scope>/<PREFIX>-NNNN-<slug>.md` | `check_decisions.py` |

`HYAI-ART-01`. `<scope>` отчёта — `project`, `kit` или имя активного домена. Отчёт домена лежит в каталоге своего домена: профиль работает внутри домена и на его территории, поэтому `HYAI/meta/reports/software/` общий для `code`, `architect` и `analysis`.
`HYAI-ART-02`. Отчёт без `domain` и `profile` в frontmatter не существует: эти поля фиксируют, кто и в какой области работал (`HYAI-INT-01`).
`HYAI-ART-03`. Имя файла — `YYYY-MM-DD-<slug>.md`, `slug` — латиница, цифры, дефис.
`HYAI-ART-04`. Обязательные разделы задаёт `report.kinds.<kind>.required_sections` в манифесте. Политика и шаблон читают один источник; расхождение — ошибка CI, а не повод для спора.

## 2. Виды отчётов

| `report_kind` | Когда | Проверяемый результат |
| --- | --- | --- |
| `task` | Изменение уже согласовано | Дифф + прогон проверок |
| `audit` | Исследование без изменений | Находки с приоритетами `P0–P3` |
| `analysis` | Разбор задачи перед решением (профили `*/analysis`) | Варианты, критерии, рекомендация |

`HYAI-ART-05`. `analysis` не вносит изменений в репозиторий, кроме собственного отчёта; переход к правкам — только после явного согласия пользователя (`HYAI-INT-09`).

## 3. Шаблоны

`HYAI-ART-06`. Каждый шаблон объявляет `template_kind`:
- `output` — форма результата (отчёт, решение, спецификация);
- `request` — форма запроса (бриф на анализ, постановка задачи, форма вопроса);
- `snippet` — переиспользуемый фрагмент.

`HYAI-ART-07`. Шаблон обязан содержать поле «что делать, если данных нет»: остановиться, задать вопрос, открыть `Q-*`. Молчаливая подстановка — нарушение.
`HYAI-ART-08`. Внутри шаблона плейсхолдеры `<...>` и `{{...}}` не считаются ссылками и не проверяются линкером (`template: true`).

## 4. Индексы и навигация

`HYAI-ART-09`. Каждый каталог содержит `README.md`, описывающий **содержимое именно этого каталога** и перечисляющий его файлы и подкаталоги.
`HYAI-ART-10`. Файл `*.index.md` обязан быть перечислен в `README.md` своего каталога.
`HYAI-ART-11`. Корневой `README.md` — маршрутизатор: что где лежит и куда идти за ответом. Он не дублирует содержимое доменных README.
`HYAI-ART-12`. Реестр `HYAI/meta/registry/documents.yaml` перечисляет документы, которые агент читает первыми; `id` уникальны глобально.
`HYAI-ART-13`. Индекс отчётов `HYAI/meta/reports/README.md` перечисляет все отчёты по scope. Отчёт, отсутствующий в индексе, — ошибка.

## 4a. Удаление, архив и история

`HYAI-ART-15`. **История живёт в git, а не в файлах.** Удалённый или переписанный текст не архивируется копией рядом и не «сохраняется для истории» отдельным файлом: он остаётся в коммите. Раздел «История изменений» внутри документа запрещён — история изменений документа есть `git log --follow`. Единственное исключение — решение: оно хранится как запись своего времени и не переписывается (правило ниже).

`HYAI-ART-16`. **Сначала депрекация, потом удаление.** Порядок: пометка `status: deprecated` и ссылка на замену → выдержка (минимум одна задача) → удаление с `HYAI-PERM-G06`. Файл, на который ссылаются, удаляется только после обновления ссылок.

`HYAI-ART-17`. **Отчёты не удаляются.** Устаревший отчёт переезжает в `HYAI/meta/reports/archive/`, а не исчезает: он объясняет, почему решение было принято.

`HYAI-ART-18`. **Решение не правится по существу.** Ошибка в решении исправляется новым решением с `supersedes` (`HYAI-DEC-06`); опечатка — правится, но без изменения нормы.

`HYAI-ART-19`. **Бинарники.** Файл больше `artifacts.no_binaries_over_mb` (10 МБ) в git не попадает: внешнее хранилище и ссылка в отчёте. Изображение — иллюстрация, а не источник правила (`DOC-POL-10` в домене `docs`).

`HYAI-ART-20`. **Минимальный `.gitignore`.** В нём обязаны быть: `HYAI/meta/intermediate/`, `HYAI/meta/exports/` (если выгрузки не нужны в истории), `Exports/`, `_backups/`, `node_modules/`, `__pycache__/`, `.venv/`, секреты. Каталог, нужный в git (например, `HYAI/meta/reports/`), не игнорируется.

## 4b. Ворота перед коммитом и выгрузкой

`HYAI-ART-21`. **Ручной чек-лист перед коммитом.** Автоматика не заменяет глаза; перед коммитом проверяется то, чего движки не видят:

| Что | Как |
| --- | --- |
| Изменено только то, что нужно | `git status`, `git diff --stat` |
| Нет отладочного и временного | просмотр диффа: `print`, `TODO`, `HYAI/meta/intermediate/` |
| Норма не изменилась молча | правка `authority: invariant`/`contract` — только с решением (`HYAI-PERM-G01`) |
| Отчёт есть и в индексе | файл в `HYAI/meta/reports/<scope>/` и строка в `HYAI/meta/reports/README.md` (`HYAI-ART-13`) |
| Индексы и реестры обновлены | новый файл упомянут в `README.md` каталога (`HYAI-ART-09`) |
| Конвейер зелёный | `python3 HYAI/tools/run_checks.py` → `rc=0` |
| Понятно, что откатывать | в отчёте есть «что сделано», в коммите — одна тема |

`HYAI-ART-22`. **Ворота выгрузки.** Даже если пресет объявлен в `schema/access.yaml`, выгрузка проходит три проверки: (1) статус не ниже `status_floor` пресета; (2) в собранном каталоге нет служебного — внутренних ID, маркеров провенанса, путей репозитория, frontmatter, ссылок на решения; (3) отчёт `task` с пресетом, числом документов и результатом проверки. Выгрузка без отчёта считается незаявленной (`HYAI-PERM-G07`).

`HYAI-ART-23`. **Каркас не содержит содержания проекта.** В ядре, доменах и шаблонах живут формы, правила и проверки; имена, топонимы, экономика, языки и сюжеты конкретного мира — в продуктовых каталогах проекта (`world/`, `chapters/`, `docs/`). Пример в правиле или шаблоне помечается как пример формы («`<Имя>`, `<регион>`»), а не как факт. Внедрение каркаса в проект — отдельная явная команда адаптации: каркас не знает, в какой проект его поставили, и не должен.

## 5. Выход за пределы своего профиля

`HYAI-ART-14`. Если работа профиля требует правки в чужой зоне (`scope_secondary` другого профиля), отчёт обязан содержать поле:
```yaml
cross_scope:
  - path: "docs/api.md"
    why: "изменение контракта требует синхронной правки спецификации"
    profile: software/code
```
Без этого поля изменение считается незаявленным. Запрет не ставится — ставится требование объяснить (`HYAI-INT-10`).
