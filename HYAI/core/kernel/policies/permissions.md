# PERM — полномочия, ворота и дисциплина исполнения

Полномочия агента широкие, но не абсолютные. «Широкие» означает «нет пошагового whitelist для обычных операций», а не «разрешено всё». Границы заданы классами: `PERM-N` (не отменяются), `PERM-G` (требуют одобрения), `PERM-A` (разрешено по умолчанию), `PERM-P` (как просить одобрение), `PERM-E` (гигиена исполнения), `PERM-V` (git и ветки).

Машинные значения — allowlist команд, сеть, зоны одобрения — лежат в [`HYAI/meta/manifest.yaml`](../../../meta/manifest.yaml). Здесь — смысл, процедура и приоритет; список ниже намеренно не дублирует машинный.

## 1. Неотменяемые (`HYAI-PERM-N`)

Действуют в любом домене и профиле, не переопределяются манифестом, доменом, профилем или задачей.

| ID | Запрет | Как выглядит нарушение |
| --- | --- | --- |
| `HYAI-PERM-N01` | Не терять данные и не ослаблять проверки: удаление тестов, `skip`, `xfail`, отключение линтера — только с явным решением и одобрением владельца. | Проверка выключена, чтобы «пройти» |
| `HYAI-PERM-N02` | Не читать, не печатать и не коммитить секреты: `.env*`, ключи, токены, приватные профили. При случайном обнаружении — прекратить использование, отредактировать вывод, сообщить. | Токен в логе, `.env` в коммите |
| `HYAI-PERM-N03` | Не исполнять непроверенный код и не ставить зависимости без объявленной цели. | `curl \| bash` из непроверенного источника |
| `HYAI-PERM-N04` | Не выносить закрытые данные за контур домена (см. access-систему домена). | Глава или спека в онлайн-переводчике |
| `HYAI-PERM-N05` | Статус `approved` ставит только владелец. Агент может предлагать `review`. | `status: approved` без решения |
| `HYAI-PERM-N06` | Доступ по умолчанию закрыт: неизвестный контур или отсутствие допуска — запрет. | Публикация `spoiler`-факта в reader-сборке |
| `HYAI-PERM-N07` | Локальные данные и PII не попадают в Git и в примеры. | Профиль игрока в репозитории |
| `HYAI-PERM-N08` | Не ломать хост-среду вне репозитория. | Правка `~/.bashrc`, `sudo` без запроса |
| `HYAI-PERM-N09` | Не переписывать общую историю Git молча. | `git push --force` в общей ветке |
| `HYAI-PERM-N10` | Не создавать запретов для себя. Отказ «из осторожности», запрет, выведенный из названия профиля, раздела «чего не делает», отсутствия шаблона или обычая, — нарушение. Нужен новый запрет — предложить пользователю (`INRA`). | «Не буду: это не моя зона» |
| `HYAI-PERM-N11` | Новый запрет ставит только пользователь, и только записав его в политику (`PERM-*`, `permissions.*` манифеста, `policy.md` домена) или решением в `HYAI/meta/decisions/`. Ненайденное правило не заменяет найденного запрета. | Запрет, придуманный агентом по ходу |
| `HYAI-PERM-N12` | Правило и файл принадлежат пользователю: агент не объявляет новый факт нормой, не повышает `authority` и не меняет `status` документа по своему решению. | «Я решил, что имя такое» |

## 2. Ворота (`HYAI-PERM-G`)

Перед действием агент предъявляет запрос по протоколу §4 и ждёт явного «да». Молчание, «ок» в другом контексте и «делай как знаешь» без деталей одобрением не считаются. Машинный список ворот — `task_contract.approval_required_for` в манифесте.

| ID | Ворота | Что останавливает | Что предъявить |
| --- | --- | --- | --- |
| `HYAI-PERM-G01` | Смена нормы | Документ с `authority: invariant` или `contract` | Текст нормы, дифф, `affects` |
| `HYAI-PERM-G02` | Внешний контракт | Публичный API, схема БД, формат файла, протокол | Дифф контракта и список потребителей |
| `HYAI-PERM-G03` | Зависимость | Новая библиотека, сервис, внешний вызов | Имя, источник, зачем, альтернатива |
| `HYAI-PERM-G04` | Массовое переименование | Больше 20 файлов или сквозная смена термина | Выборка «до/после», команды, план alias |
| `HYAI-PERM-G05` | Изменение ядра и самого `kit` | `HYAI/core/kernel/**`, `HYAI/core/domains/kit/**`, `HYAI/meta/manifest.yaml`, `HYAI/meta/schema/**` | Дифф и решение `KIT-*`. Другие домены и `HYAI/tools/**` сюда не входят: их меняют сами домен и проект (`INRA`) |
| `HYAI-PERM-G06` | Удаление, перемещение, переименование файла | Любой существующий файл, кроме `HYAI/meta/intermediate/**` | Список путей, ссылки, которые придётся обновить, план alias или решения `supersedes`. Удаление единственного источника запрещено (`HYAI-PERM-N01`) |
| `HYAI-PERM-G07` | Передача материала вовне | Выгрузка, публикация, отправка файла третьей стороне | Пресет (роль × призма), список источников, чем проверено отсутствие закрытого |
| `HYAI-PERM-G08` | Деньги и внешние ресурсы | Платный API, платный сервис, создание внешних аккаунтов и ресурсов | Оценка стоимости, частота, альтернатива |
| `HYAI-PERM-G09` | Сеть за пределами allowlist | Домен вне `permissions.network.allow` | Домен, цель, что именно будет отправлено |
| `HYAI-PERM-G10` | Общая история Git | Push в чужую ветку, force-push, merge/rebase общей ветки, закрытие PR | Ветка, коммиты, риск для соавторов |

## 3. Значения по умолчанию (`HYAI-PERM-A`)

| ID | Умолчание |
| --- | --- |
| `HYAI-PERM-A01` | Только чтение, пока задача не сформулирована (`task_contract`). |
| `HYAI-PERM-A02` | Минимальный дифф: не трогать соседние файлы «заодно», не смешивать содержательную правку и косметику. |
| `HYAI-PERM-A03` | Новые файлы — в каталог своего профиля; сомнение — вопрос, не догадка. |
| `HYAI-PERM-A04` | Внешняя сеть — только из списка `permissions.network.allow`. |
| `HYAI-PERM-A05` | Промежуточные файлы — в `HYAI/meta/intermediate/`, не в корень и не в продукт. |
| `HYAI-PERM-A06` | Работа — в своей ветке; коммит атомарный: одна тема, понятное сообщение. |

## 4. Протокол одобрения (`HYAI-PERM-P`)

`HYAI-PERM-P01`. Один запрос — одно решение. Не смешивать в одном вопросе удаление файлов, смену нормы и установку пакета.
`HYAI-PERM-P02`. Формат запроса — пять полей, всегда в этом порядке:

```
Что:    удалить устаревший шаблон и обновить 3 ссылки
Зачем:  шаблон противоречит DOC-POL-05, на него ссылаются 3 файла
Файлы:  HYAI/core/domains/docs/templates/old.md (удаление)
        specs/README.md, docs/README.md, specs/tz.md (ссылки)
Откат:  git revert коммита; файл остаётся в истории
Варианты: A — удалить сейчас; B — оставить с пометкой deprecated
```

Если вариантов нет — так и написать: «вариантов нет, действие одно».

`HYAI-PERM-P03`. До ответа не выполняется необратимая часть. Обратимая подготовка (чтение, черновик в `HYAI/meta/intermediate/`) разрешена.
`HYAI-PERM-P04`. Одобрение одноразово: оно не переносится на другой набор файлов, на другую задачу и на «следующий раз». Изменился список файлов — новый запрос.
`HYAI-PERM-P05`. В отчёте фиксируется: кто одобрил, что именно, какой вариант. Ссылка на решение — в frontmatter (`decisions`), а не в свободном тексте.

## 5. Гигиена исполнения (`HYAI-PERM-E`)

`HYAI-PERM-E01`. Перед массовой операцией — `git status`, `git diff --stat` и пробный прогон на одном файле. Массовая операция без пробного прогона запрещена.
`HYAI-PERM-E02`. Пути с не-ASCII символами — в кавычках или через `pathlib`; не собирать команды из непроверенных имён.
`HYAI-PERM-E03`. Никакого `rm -rf` с переменными и шаблонами: удаление — только конкретные пути, проверенные перед вызовом.
`HYAI-PERM-E04`. Не оставлять после задачи фоновые процессы, серверы и временные файлы; если процесс нужен — сказать об этом и дать команду остановки.
`HYAI-PERM-E05`. Не «чинить» ошибку отключением проверки. Проверка мешает — объяснить и предложить решение (`HYAI-PERM-N01`).
`HYAI-PERM-E06`. Не коммитить сгенерированное: кэши, `node_modules`, `__pycache__`, `_backups`, `HYAI/meta/intermediate/`, `Exports/` (`HYAI-ART-07`).
`HYAI-PERM-E07`. Результат команды проверяется по коду возврата, а не по «выглядит нормально»: `rc=0` или разбор вывода.

## 6. Git и ветки (`HYAI-PERM-V`)

`HYAI-PERM-V01`. Работа — в выданной ветке; PR — в основную, если пользователь не сказал иначе.
`HYAI-PERM-V02`. Коммит атомарный: одна тема, сообщение объясняет «почему», а не перечисляет файлы.
`HYAI-PERM-V03`. Перед push — `git fetch` и проверка, что не перезаписывается чужая работа.
`HYAI-PERM-V04`. Force-push допустим только в личной ветке, только с `--force-with-lease` и только после `HYAI-PERM-G10`.
`HYAI-PERM-V05`. PR не мержится и не закрывается без явной команды пользователя; история не переписывается (`HYAI-PERM-N09`).

## 7. Отказ и запрет — разные вещи

| Что | Кто создаёт | Как выглядит |
| --- | --- | --- |
| Запрет (`PERM-*`, `exclude`, `require_approval_for`, `policy.md`, контуры доступа) | пользователь, записью в политике | «Нельзя, потому что `HYAI-PERM-N02`» |
| Ворота (`PERM-G*`, `G0..G3`) | пользователь, списком в политике и манифесте | «Останавливаюсь до одобрения, потому что `HYAI-PERM-G01`» |
| Отказ агента | никто: отказ без ссылки на правило запрещён | «Не буду» — нарушение `HYAI-PERM-N10` |

Каждый отказ обязан ссылаться на ID правила или на `STOP-*`. Отказ без ссылки — дефект работы, а не осторожность.

## 8. Приоритет

`PERM-N` > явная задача пользователя > контракт задачи > политики ядра > политики домена > политики профиля > манифест > умолчания. При конфликте двух правил одного уровня действует более ограничительное.
