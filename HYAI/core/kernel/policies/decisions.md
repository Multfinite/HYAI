# DEC — решения

Решение фиксирует **действующую норму**, а не историю обсуждения. Файл решения читают, чтобы узнать «как правильно сейчас», а не «что когда-то решили».

## 1. Область решения

`HYAI-DEC-01`. Каждое решение объявляет `scope` — одно из значений `decisions.scopes` манифеста: `project` или имя домена.
`HYAI-DEC-02`. Решение, касающееся двух и более доменов, живёт в `project` и ссылается на затронутые домены: `affects_domains: [software, narrative]`. Прятать междоменное решение в каталоге одного домена запрещено.
`HYAI-DEC-03`. Решение о формате каркаса (новый домен, новый профиль, новая проверка) — `scope: kit`.
`HYAI-DEC-04`. `affects` перечисляет реальные пути. Путь, которого нет, — ошибка: решение ссылается на код или документ, которых не существует.

## 2. Идентификаторы

`HYAI-DEC-05`. Формат — `<PREFIX>-NNNN`, префикс из `decisions.scopes.<scope>.prefix`. Нумерация независима внутри области: `SW-0007` и `NR-0007` — разные решения.
`HYAI-DEC-06`. Номер неизменен. Изменение нормы — новое решение со ссылкой `supersedes: SW-0007`.
`HYAI-DEC-07`. Дубль идентификатора в пределах области — ошибка.

## 3. Норма вместо журнала

`HYAI-DEC-08`. В файле — только действующая норма, контекст «почему» в 3–5 строк и последствия. Хронология изменений не ведётся.
`HYAI-DEC-09`. Уточнение существующего решения не создаёт новый файл: оно вливается в исходное, а номер-«вход» получает заглушку `status: merged`, `merged_into: SW-0003`.
`HYAI-DEC-10`. `status: superseded` требует `superseded_by`; `status: merged` — `merged_into`; обе ссылки обязаны существовать.
`HYAI-DEC-11`. Бюджет — `decisions.max_lines` (120 строк). Превышение означает, что в файле два решения: разделить.
`HYAI-DEC-12`. Один предмет — один файл. Два решения об одном и том же — ошибка, лечится слиянием (`HYAI-DEC-09`).

## 4. Индекс

`HYAI-DEC-13`. `HYAI/meta/decisions/README.md` перечисляет все решения по областям и обязан совпадать с файловой системой в обе стороны: файл без строки в индексе и строка без файла — ошибки.

## 5. Смысл решения (`HYAI-DEC-14..19`)

Правила ниже восстановлены из исходной политики и действуют вместе с формальными (`HYAI-DEC-01..13`).

`HYAI-DEC-14`. **Решение фиксирует норму, а не работу.** Список правок, «что сделано» и перечень файлов — в отчёт, не в решение. Решение отвечает на вопрос «как теперь правильно», а не «что я сделал».
`HYAI-DEC-15`. **Правило вместо перечисления.** Если решение перечисляет N однотипных фактов, оно формулирует правило и ссылается на карточку, где лежат данные. Перечни стареют, правило — нет.
`HYAI-DEC-16`. **Выводимое не решается.** Если следствие вытекает из принятой нормы, оно пишется в документ с маркером `[В]` (`HYAI-PROV-01`), а не оформляется решением. Решение нужно там, где возможен выбор.
`HYAI-DEC-17`. **Номер не переиспользуется.** Номер решения и номер правила (`HYAI-…`, `SW-…`, `NR-…`) занят навсегда, даже если файл удалён: иначе старые ссылки начнут врать. Вышедшие номера фиксируются в [`HYAI/meta/schema/rule-ids.yaml`](../../../meta/schema/rule-ids.yaml) и в истории git; схема — [`../spec/rule-ids.md`](../spec/rule-ids.md).
`HYAI-DEC-18`. **Смысл утверждает пользователь, форму — агент.** Механическое слияние дублей без изменения нормы агент делает сам (`HYAI-DEC-09`); слияние или уточнение, меняющее смысл нормы, проходит через ворота `HYAI-PERM-G01`.
`HYAI-DEC-19`. **Структура файла решения:** «Решение» → «Почему» → «Границы» (что норма **не** значит) → «Открытые вопросы». Раздел «Что сделать» не нужен: к моменту записи решения изменения уже сделаны или запланированы в отчёте. Объём — `decisions.max_lines` (`HYAI-DEC-11`), раздел «История» не ведётся (`HYAI-ART-15`).
