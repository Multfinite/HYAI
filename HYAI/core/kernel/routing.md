# Маршрутизация задачи

Документ исполняет `HYAI-INT-01..04`: превращает формулировку задачи в пару «домен + профиль». Он же — основание для классификатора, которым пользуется агент, когда пользователь просит решить самому.

## 1. Порядок определения

1. **Явное указание.** Пользователь назвал домен и/или профиль — берём их (`HYAI-INT-02`).
2. **Артефакт задачи.** Что нужно получить? Код — `software/code`; проектную схему — `software/architect`; разбор — `*/analysis`; фрагмент мира — `narrative/lore`; согласованную хронологию — `narrative/history`; текст — `narrative/prose`; домен или профиль — `kit/*`.
3. **Путь из задачи.** Если назван файл или каталог, домен берётся из `path_map` манифеста (`src/**` → `software`, `world/**` → `narrative`).
4. **Не определено.** Один вопрос пользователю или 2–3 варианта с ценой; при отказе «реши сам» — выбор агента, объявленный одной строкой.

## 2. Домены

| Домен | Триггеры | Чего домен не делает |
| --- | --- | --- |
| `software` | код, тесты, зависимости, API, схема данных, производительность, сборка, архитектура ПО | не пишет художественный текст и не устанавливает факты мира |
| `narrative` | мир, персонажи, хронология, черновики, стиль, канон, противоречия в тексте | не меняет код и не проектирует ПО |
| `kit` | новый домен, новый профиль, новая проверка, правила каркаса | **не меняет сам себя** и не меняет ядро (политика KIT) |

## 3. Профили

| Профиль | Что делает | Типичный результат |
| --- | --- | --- |
| `software/code` | реализует по согласованному контракту | код, тесты, отчёт `task` |
| `software/architect` | проектирует: границы, контракты, схемы, миграции | спека, ADR `SW-*`, модульная карточка |
| `software/analysis` | разбирает задачу перед решением | отчёт `analysis`, список `Q-*` |
| `narrative/lore` | создаёт и правит факты мира | карточка сущности |
| `narrative/history` | согласует хронологию и инварианты мира | таймлайн, правка противоречий |
| `narrative/prose` | пишет и чистит текст, не меняя фактов | сцена, отчёт `task` |
| `narrative/analysis` | ищет противоречия и пробелы в корпусе | отчёт `analysis` |

`*/analysis` включается только по просьбе пользователя (`HYAI-INT-08`).

## 4. Что делать при пограничной задаче

| Ситуация | Решение |
| --- | --- |
| Правка кода требует правки спеки | Домен `software`, ведущий профиль по артефакту задачи; спека объявляется в `cross_scope` |
| Сцена требует нового факта мира | `narrative/prose` как ведущий, факт — в `cross_scope` и отдельной карточкой `lore` |
| Задача про каркас и про код одновременно | Две задачи: сначала `kit` (правило), затем `software` (применение) |
| Задача не про продукт, а про правила | `kit` |

## 5. Фиксация выбора

Выбор попадает в два места: сообщение пользователю (`HYAI-INT-04`) и frontmatter отчёта (`HYAI-ART-02`, поля `domain` и `profile`). Расхождение с каталогом отчёта ловит `check_report.py`.
