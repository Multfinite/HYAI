# `audit` — исследование

Результат аудита — отчёт, а не правки. Правки — отдельная задача после согласования находок.

## Порядок

1. **Рамка.** Что проверяем, по каким критериям, что заведомо вне охвата. Критерии берутся из политик домена и `architecture` домена, а не из головы.
2. **Сбор.** Каждая находка: место (`путь:строка`), наблюдение, нарушенное правило с ID, последствие, приоритет `P0–P3`.
3. **Проверка находок.** `P0` и `P1` подтверждаются воспроизведением или цитатой нормы. Неподтверждённое — `[Г]` с пометкой, что нужно для подтверждения.
4. **Предложения.** Каждое — с ценой и риском; «переписать всё» не предложение.
5. **Отчёт** `HYAI/meta/reports/<domain>/…-audit-….md` по шаблону `kernel/templates/audit-report.md`, `report_kind: audit`.

## Ограничения

- Никаких правок в репозитории, кроме отчёта.
- Нельзя превращать аудит в поиск виноватых: находка адресуется файлу и правилу, не человеку.
- Пропущенная область объявляется, а не замалчивается: «не проверял `X`, потому что `Y`».
