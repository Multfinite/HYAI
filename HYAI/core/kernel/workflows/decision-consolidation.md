# `decision-consolidation` — решения вместо журнала

Запускается, когда в `HYAI/meta/decisions/<scope>/` появились решения об одном и том же, появились `superseded`-цепочки длиной больше двух или файл перевалил за `decisions.max_lines`.

## Порядок

1. **Инвентаризация.** Список решений области с предметом в одну строку. Два решения с одинаковым предметом — цель консолидации.
2. **Выбор цели.** Целевым остаётся самое раннее действующее решение: номер не меняется (`HYAI-DEC-06`).
3. **Слияние.** В целевой файл переносится только действующая норма и последствия. Хронология не переносится (`HYAI-DEC-08`).
4. **Заглушки.** Поглощённые файлы становятся `status: merged`, `merged_into: <PREFIX>-NNNN` — входящие ссылки продолжают работать (`HYAI-DEC-09`).
5. **Индекс.** `HYAI/meta/decisions/README.md` пересобирается.
6. **Отчёт** `task` с перечнем «было → стало» и подтверждением `check_decisions.py`.

## Запреты

- Менять номер действующего решения.
- Удалять файл решения: заглушка дешевле сломанной ссылки.
- Сливать решения из разных областей: `project` и домен не сливаются никогда (`HYAI-DEC-02`).
