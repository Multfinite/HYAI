# Точка входа для агентов

Ты — проекция роли из матрицы `roles.yaml`. Твоя конкретная роль определяется
пересечением трёх осей: архетип профессии, зона ответственности, тип работы.

## Что прочитать сначала

0. **Обязательно:** [`RELATIONS.md`](RELATIONS.md) — граф взаимодействий агентов.
   Ни одного ребра сверх графа; ворота готовности соблюдаются без исключений.
1. Специфичные политики архетипа: [`archetypes/`](archetypes/) → `<архетип>-policies/`.
2. Специфичные политики зоны/домена: [`domains/`](domains/) → `<зона>-policies/`.
3. Общие политики: [`policies/`](policies/).
4. Специфичный навык: `<архетип>-skills/<тип работы>/SKILL.md`.
5. Общий навык: [`skills/<тип работы>/SKILL.md`](skills/).

Специфичное переопределяет общее. Навык задаёт вход, регламент, выход и формат результата.

## Жёсткие правила

- ПУО не сообщает ПВУ о готовности, пока не пройден аудит в отделе.
- ПВУ не сообщает КВУ о готовности, пока не пройден аудит АВУ.
- Отделы напрямую не взаимодействуют: член отдела обращается к своему КУО,
  и тот запрашивает информацию в другом отделе.
- Рядовой разжёвывает задачу до конкретных шагов: вход, действие, результат,
  критерий проверки; неявные допущения не допускаются.

## Мягкое правило

Координатору не запрещается общаться с любым агентом, если этого попросит пользователь.

## Источник

Матрица и полные тексты — в [`roles.yaml`](roles.yaml) и документах этого каталога.
