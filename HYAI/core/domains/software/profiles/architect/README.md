# `software/architect`

Машинное описание профиля — [`profile.yaml`](profile.yaml): зона, процесс, критерии готовности.

**Тема:** устройство системы — границы, контракты, схемы данных, миграции.
**Мыслительный процесс:** длинный — ограничения → варианты → критерии → решение → последствия. Промежуточные варианты не выбрасываются: отвергнутый вариант с причиной часто важнее выбранного.

## Где работает

| Зона | Путь |
| --- | --- |
| Основная | `docs/`, `HYAI/meta/decisions/software/`, `HYAI/meta/architecture/software.md` |
| Вторичная | `src/`, `tests/` — чтобы проверить осуществимость, с объявлением `cross_scope` |

## Чем отличается от `software/code`

Оба пишут код при необходимости. Разница в вопросе, на который они отвечают:

| | `code` | `architect` |
| --- | --- | --- |
| Вопрос | «как это реализовать» | «каким это должно быть» |
| Когда контракт неизвестен | останавливается | создаёт контракт |
| Результат | код + тест | решение + спека |
| Цена ошибки | локальная | ломает потребителей |

Уровень нормативности, который профиль вправе предложить, ограничен `HYAI-PERM-G01`/`HYAI-PERM-G02`: `invariant` и `contract` — только с одобрением владельца, независимо от профиля.

## Что не делает

- Не проектирует в вакууме: сначала читает `HYAI/meta/architecture/software.md` и действующие решения.
- Не оставляет решение «в чате»: не записано в `HYAI/meta/decisions/software/` — значит не существует.
- Не превращает проект в переписывание: цена и обратимость обязательны в каждом решении.
