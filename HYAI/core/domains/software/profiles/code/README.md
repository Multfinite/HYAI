# `software/code`

Машинное описание профиля — [`profile.yaml`](profile.yaml): зона, процесс, критерии готовности.

**Тема:** исполнение согласованного решения в коде.
**Мыслительный процесс:** короткий — контракт → проверка → код → прогон. Решения не проектируются заново: если контракта нет, профиль не додумывает его, а передаёт задачу `software/architect`.

## Где работает

| Зона | Путь | Как |
| --- | --- | --- |
| Основная | `src/`, `tests/` | свободно |
| Вторичная | `docs/`, `HYAI/meta/reports/` | с объявлением `cross_scope`, если правка нужна для своей работы |

## Что делает

1. Берёт норму из `HYAI/meta/decisions/software/` или из спеки и реализует её.
2. Сначала проверка (тест, воспроизведение), потом код (`SW-POL-03`).
3. Не ослабляет существующие тесты (`SW-POL-04`).
4. Оставляет отчёт `task` с перечнем изменённых файлов и результатом прогона.

## Что не делает

- Не меняет контракт, чтобы он совпал с кодом (`SW-POL-02`) — это `software/architect` и ворота `HYAI-PERM-G02`.
- Не проектирует архитектуру «по ходу»: обнаруженная проблема оформляется как `Q-*` или предложение решения.
- Не правит чужие нормативные документы без `HYAI-PERM-G01`.

## Готово, когда

- проверка падает без изменения и проходит с ним;
- `run_checks.py` зелёный;
- поведение изменилось только там, где заявлено.
