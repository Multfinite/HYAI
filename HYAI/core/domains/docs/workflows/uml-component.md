# `docs/uml-component`

Регламент: [`uml.md`](../uml.md); общие правила `DOC-POL-16..20`, правило типа `DOC-POL-22`, базовые `DOC-POL-10..12` — в [`policy.md`](../policy.md).

1. **Вопрос.** Какие части системы и через какие интерфейсы общаются. Граница компонента — единица сборки или модуль, а не отдельный файл.
2. **Источник.** Манифест сборки, конфигурация модулей, контракты API. Путь записать в шапку (`DOC-POL-17`).
3. **Нотация.** PlantUML `componentDiagram` или Mermaid, текстовый файл рядом с документом (`DOC-POL-19`).
4. **Шапка.** ID, вопрос, читатель, тип `component`, нотация, источник, версия сборки (`DOC-POL-18`).
5. **Элементы.** Компоненты, предоставляемые интерфейсы (шар), требуемые интерфейсы (гнездо), порты, артефакты.
6. **Связи.** Делегирование, зависимость и сборка «предоставляемый → требуемый». Каждый интерфейс имеет контракт в источнике.
7. **Проверка.** Границы совпадают с единицей поставки; интерфейсы не пустые; лишние зависимости убраны (`DOC-POL-20`).
8. **Публикация.** Картинка — выгрузка рядом; правка идёт в текст схемы.

## Готово, когда

- Компоненты соответствуют модулям или артефактам сборки.
- Каждый интерфейс подписан и имеет контракт.
- Классы не выданы за компоненты без причины.
