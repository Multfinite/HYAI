# `docs/spec`

1. **Потребность.** Кто заказчик, какую задачу решаем, что будет считаться успехом. Без этого требования начнут расти в стороны.
2. **Границы.** Что входит, что явно вне охвата (`non_goals`). Вне охвата фиксируется так же строго, как охват.
3. **Требования.** Каждое: `REQ-NN`, формулировка, источник (`[А]`/`[И]`), критерий приёмки, приоритет. Проверяемое — тестом, измерением или осмотром (`DOC-POL-01`).
4. **Конфликты.** Два требования, которые нельзя выполнить одновременно, называются явно и разрешаются решением, а не молчанием.
5. **Проверка.** Пройти по каждому `REQ` и ответить: как узнаем, что выполнено. Нет ответа — требование переформулировать.
6. **Согласование.** Статус `approved` ставит владелец (`HYAI-PERM-N05`). До этого документ — `draft`.

Ворота: `HYAI-PERM-G01` при изменении утверждённого ТЗ — оно меняет то, что делают другие.
