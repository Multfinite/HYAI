# `docs/uml-interaction-overview`

Регламент: [`uml.md`](../uml.md); общие правила `DOC-POL-16..20`, правило типа `DOC-POL-34`, базовые `DOC-POL-10..12` — в [`policy.md`](../policy.md).

1. **Вопрос.** В каком порядке выполняются фрагменты взаимодействий и где точки ветвления. Внутреннее содержимое последовательности не вставляется целиком.
2. **Источник.** Сценарий верхнего уровня, набор диаграмм последовательности, контракт оркестратора (`DOC-POL-17`).
3. **Нотация.** PlantUML для interaction overview или Mermaid, текстовый файл рядом с документом (`DOC-POL-19`).
4. **Шапка.** ID, вопрос, читатель, тип `interaction overview`, нотация, источник, дата среза (`DOC-POL-18`).
5. **Элементы.** Фрагмент взаимодействия со ссылкой на sequence-диаграмму, действие, решение, начальная и конечная точки, дорожки.
6. **Связи.** Поток управления между фрагментами; ссылка на отдельную диаграмму последовательности.
7. **Проверка.** Каждый фрагмент указывает на свою sequence-диаграмму; ветвления имеют условия; поток не имеет тупиков (`DOC-POL-20`).
8. **Публикация.** Картинка — выгрузка рядом; правка идёт в текст схемы.

## Готово, когда

- Все фрагменты имеют ссылки на свои sequence-диаграммы.
- Ветвления подписаны условиями.
- Нет тупиковых ветвей.
