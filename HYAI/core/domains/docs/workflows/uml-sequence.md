# `docs/uml-sequence`

Регламент: [`uml.md`](../uml.md); общие правила `DOC-POL-16..20`, правило типа `DOC-POL-31`, базовые `DOC-POL-10..12` — в [`policy.md`](../policy.md).

1. **Вопрос.** Кто кому и в каком порядке отправляет сообщения. Порядок задаёт смысл, стрелки идут сверху вниз по времени.
2. **Источник.** Трассировка вызовов, контракт API, сценарий варианта использования (`DOC-POL-17`).
3. **Нотация.** PlantUML `sequenceDiagram` или Mermaid `sequenceDiagram`, текстовый файл (`DOC-POL-19`).
4. **Шапка.** ID, вопрос, читатель, тип `sequence`, нотация, источник, дата среза (`DOC-POL-18`).
5. **Элементы.** Линии жизни, активации, синхронные и асинхронные сообщения, комментарии.
6. **Связи.** Вызовы по времени; фрагменты `alt`, `opt`, `loop`, `par`, `break` с условиями и границами.
7. **Проверка.** Порядок совпадает с трассировкой; у сообщений есть получатель; у фрагментов — условия (`DOC-POL-20`).
8. **Публикация.** Картинка — выгрузка рядом; правка идёт в текст схемы.

## Готово, когда

- Порядок сообщений подтверждён трассировкой.
- Каждое сообщение имеет отправителя и получателя.
- Фрагменты имеют условия и границы.
