# `docs/uml-use-case`

Регламент: [`uml.md`](../uml.md); общие правила `DOC-POL-16..20`, правило типа `DOC-POL-29`, базовые `DOC-POL-10..12` — в [`policy.md`](../policy.md).

1. **Вопрос.** Кто и зачем взаимодействует с системой и где проходит её граница. Каждый вариант имеет `REQ-ID` и текст сценария в документе.
2. **Источник.** ТЗ, интервью, список требований с `REQ-ID` (`DOC-POL-17`).
3. **Нотация.** PlantUML `usecaseDiagram` или Mermaid, текстовый файл рядом с документом (`DOC-POL-19`).
4. **Шапка.** ID, вопрос, читатель, тип `use case`, нотация, источник, дата среза (`DOC-POL-18`).
5. **Элементы.** Акторы, варианты использования, граница системы, пакеты вариантов. Овал — не текст сценария.
6. **Связи.** Ассоциация «актор — вариант», `include`, `extend`, обобщение акторов и вариантов.
7. **Проверка.** У каждого варианта есть требование и сценарий в тексте; граница нарисована; лишние акторы убраны (`DOC-POL-20`).
8. **Публикация.** Картинка — выгрузка рядом; правка идёт в текст схемы.

## Готово, когда

- Граница системы явно обозначена.
- Каждый вариант связан с `REQ-ID`.
- Текст сценария остаётся в документе, а не в овале.
