# `docs/diagrams`

1. **Вопрос.** Что должно стать понятно из схемы. Если ответ «всё сразу» — схема не нужна (`DOC-POL-11`).
2. **Тип.** Структура — C4/классы; поток — sequence/activity; состояния — state machine; данные — ER. Тип выбирается по вопросу, а не по привычке.
3. **Источник.** Схема строится по коду, документу или требованию, а не по памяти. Расхождения с источником — `Q-*`.
4. **Текст.** Mermaid, PlantUML, Graphviz или D2 в файле рядом с документом (`DOC-POL-10`). Подписи связей обязательны.
5. **Проверка.** Схема рендерится; обозначения совпадают с текстом документа; лишние сущности убраны.
6. **Публикация.** Картинка — выгрузка, не источник. Правка идёт в текст схемы.
