# `docs/uml-state-machine`

Регламент: [`uml.md`](../uml.md); общие правила `DOC-POL-16..20`, правило типа `DOC-POL-30`, базовые `DOC-POL-10..12` — в [`policy.md`](../policy.md).

1. **Вопрос.** Какие состояния проходит объект и по каким событиям переходит между ними. Диаграмма не подменяет активность.
2. **Источник.** Конечный автомат в коде, контракт сущности, спецификация протокола (`DOC-POL-17`).
3. **Нотация.** PlantUML `stateDiagram-v2` или Mermaid `stateDiagram-v2`, текстовый файл (`DOC-POL-19`).
4. **Шапка.** ID, вопрос, читатель, тип `state machine`, нотация, источник, дата среза (`DOC-POL-18`).
5. **Элементы.** Состояния, начальное и конечное, вложенные состояния, history-псевдосостояние.
6. **Связи.** Переход с меткой «событие [условие] / действие», составные переходы. Переход без события не рисуется.
7. **Проверка.** Каждый переход соответствует событию в источнике; тупиковых состояний нет, кроме конечных (`DOC-POL-20`).
8. **Публикация.** Картинка — выгрузка рядом; правка идёт в текст схемы.

## Готово, когда

- Все состояния и события найдены в источнике.
- Условия и действия подписаны.
- Нет тупиковых состояний, кроме конечных.
