# `docs/uml-communication`

Регламент: [`uml.md`](../uml.md); общие правила `DOC-POL-16..20`, правило типа `DOC-POL-32`, базовые `DOC-POL-10..12` — в [`policy.md`](../policy.md).

1. **Вопрос.** Кто с кем связан и какие сообщения идут по этим связям. Акцент на топологии, а не на времени.
2. **Источник.** Граф вызовов, конфигурация связей объектов, та же трассировка, что и для последовательности (`DOC-POL-17`).
3. **Нотация.** PlantUML для коммуникации или Mermaid, текстовый файл рядом с документом (`DOC-POL-19`).
4. **Шапка.** ID, вопрос, читатель, тип `communication`, нотация, источник, дата среза (`DOC-POL-18`).
5. **Элементы.** Объекты, связи, составные сообщения, стереотипы ссылок. Каждый объект есть в источнике.
6. **Связи.** Нумерованные сообщения (`1`, `1.1`, `2`) с меткой и направлением; порядок задаётся номером, а не положением стрелки.
7. **Проверка.** Номера согласованы с порядком в трассировке; время не передаётся стрелками; дублирование последовательности оправдано (`DOC-POL-20`).
8. **Публикация.** Картинка — выгрузка рядом; правка идёт в текст схемы.

## Готово, когда

- Нумерация сообщений полная и не имеет пропусков.
- Связи соответствуют объектам из источника.
- Диаграмма не пытается показать время.
