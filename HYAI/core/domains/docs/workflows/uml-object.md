# `docs/uml-object`

Регламент: [`uml.md`](../uml.md); общие правила `DOC-POL-16..20`, правило типа `DOC-POL-24`, базовые `DOC-POL-10..12` — в [`policy.md`](../policy.md).

1. **Вопрос.** Как выглядит состояние системы в конкретный момент. Момент среза указывается в шапке.
2. **Источник.** Тестовые фикстуры, снимок состояния, лог или пример из спецификации (`DOC-POL-17`).
3. **Нотация.** PlantUML `objectDiagram` или Mermaid, текстовый файл рядом с документом (`DOC-POL-19`).
4. **Шапка.** ID, вопрос, читатель, тип `object`, нотация, источник, момент среза (`DOC-POL-18`).
5. **Элементы.** Объекты с именами и значениями атрибутов, ссылка на тип; определения классов на схеме не повторяются.
6. **Связи.** Только реально существующие в момент среза связи, с метками и кратностью.
7. **Проверка.** Снимок воспроизводится из фикстуры; значения не выдуманы; лишние объекты убраны (`DOC-POL-20`).
8. **Публикация.** Картинка — выгрузка рядом; правка идёт в текст схемы.

## Готово, когда

- Момент среза зафиксирован.
- Каждое значение есть в источнике.
- Диаграмма не подменяет классовую.
