# `docs/uml-profile`

Регламент: [`uml.md`](../uml.md); общие правила `DOC-POL-16..20`, правило типа `DOC-POL-26`, базовые `DOC-POL-10..12` — в [`policy.md`](../policy.md).

1. **Вопрос.** Какие стереотипы и ограничения применяются к модели и где именно. Новый стереотип требует решения `DOC-*`.
2. **Источник.** Решение `DOC-*`, схема метамодели, конфигурация инструмента моделирования (`DOC-POL-17`).
3. **Нотация.** PlantUML для профилей или Mermaid, текстовый файл рядом с документом (`DOC-POL-19`).
4. **Шапка.** ID, вопрос, читатель, тип `profile`, нотация, источник, решение `DOC-*` (`DOC-POL-18`).
5. **Элементы.** Профиль, стереотип, метакласс, ограничение (OCL или текст), расширение `extend`. Стереотип без метакласса не рисуется.
6. **Связи.** Применение профиля (`profile application`) к пакету или модели, показано явно.
7. **Проверка.** У каждого стереотипа есть метакласс и ограничение; применение профиля не подразумевается молча (`DOC-POL-20`).
8. **Публикация.** Картинка — выгрузка рядом; правка идёт в текст схемы.

## Готово, когда

- Все стереотипы имеют метаклассы и ограничения.
- Применение профиля указано явно.
- Новые стереотипы зафиксированы решением `DOC-*`.
