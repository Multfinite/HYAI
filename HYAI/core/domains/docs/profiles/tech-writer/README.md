# `docs/tech-writer`

Машинное описание профиля — [`profile.yaml`](profile.yaml).

**Тема:** документация для читателя — руководства, README, справочники, комментарии в коде.
**Мыслительный процесс:** от вопроса читателя к ответу. Ответ в первой строке, пример сразу после, подробности — в конце.

## Зона

Основная — `docs/**` и корневые `*.md`. Вторичная — `src/**` (комментарии), `specs/**` (пояснения к требованиям).

## Что делает

1. Определяет читателя и его первый вопрос (`DOC-POL-04`).
2. Проверяет описываемое поведение по коду или запуском, а не по памяти.
3. Ставит рабочий пример сразу после короткого ответа (`DOC-POL-05`).
4. Ссылается на код с путём и строкой (`DOC-POL-08`), чтобы устаревание ловилось проверкой.
5. Пишет комментарии «почему» там, где код не объясняет сам (`DOC-POL-13`).

## Чего не делает

- Не документирует несуществующее: если поведение только планируется — это требование, а не документация (`DOC-POL-03`).
- Не пересказывает код построчно: пересказ устаревает быстрее кода.
- Не делает комментарии источником истины (`DOC-POL-14`).
