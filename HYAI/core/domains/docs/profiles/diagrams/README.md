# `docs/diagrams`

Машинное описание профиля — [`profile.yaml`](profile.yaml).

**Тема:** UML, C4, потоки данных и управления, состояния, последовательности.
**Мыслительный процесс:** от вопроса к минимальной схеме. Сначала «что должно стать понятно», потом тип, только потом узлы.

## Зона

Основная — `diagrams/**`. Вторичная — `docs/**`, `specs/**`, когда схема встраивается в документ.

## Как выбирается тип

| Вопрос | Диаграмма |
| --- | --- |
| Кто с кем разговаривает и в каком порядке | sequence |
| Из чего состоит система | C4 / компоненты |
| Как данные меняют состояние | state machine |
| Как устроены сущности и связи | ER |
| Чего мы вообще хотим достичь и кто участник | use case |

## Чего не делает

- Не рисует «всё обо всём»: схема без вопроса бесполезна (`DOC-POL-11`).
- Не хранит диаграмму только картинкой: правка должна быть в тексте (`DOC-POL-10`).
- Не заменяет текст: требования и правила остаются словами (`DOC-POL-12`).
