# Шкала компетенции `УН–У14`

Шкала нужна для двух вещей: понять, **что персонаж умеет** на своём уровне, и сформулировать границу в «Карте понимания» («знает до …»). Это не рейтинг силы и не уровень доступа: доступ решает пара «роль × призма» ([`access.md`](access.md)), а уровень говорит, насколько субъект понимает тему.

**`УН` — вне шкалы.** Это не «нулевой уровень», а отсутствие знания: темы нет в профиле. `УН` запрещает понимание, но не знание — персонаж может знать факт (слух, чужой пересказ) и не понимать его.

## Таблица

| Код | Название | Что это значит |
| --- | --- | --- |
| `УН` | Неспособный | Темы нет в профиле. Знание факта возможно, понимание — нет |
| `У0` | Нетренированный | Бытовые представления из среды, слухов и массовой культуры; без системы |
| `У1` | Неопытный | Знаком с концепцией, но не с деталями и не с практикой |
| `У2` | Новичок | Любитель: минимальный практический опыт или хобби |
| `У3` | Компетентный | Уверенно понимает базовые механизмы, но не системные связи |
| `У4` | Опытный | Крепкий линейный специалист: работает по стандартным протоколам |
| `У5` | Умелый | Решает нестандартные задачи, применяет творческий подход |
| `У6` | Профессионал | Высококлассный специалист с подтверждённой ценностью на рынке |
| `У7` | Ветеран | Глубокий опыт; знает пределы дисциплины — «что можно и чего нельзя» |
| `У8` | Эксперт | Редкий талант; за таких конкурируют организации |
| `У9` | Выдающийся | Имя становится синонимом дисциплины |
| `У10` | Элита | Признанный авторитет даже среди экспертов высшего эшелона |
| `У11` | Легенда | Исторический эталон; в честь него называют институты и законы |
| `У12` | Вершина | Предел физиологически смертного существа |
| `У13` | Гений | Прорывное понимание сверх человеческого; требует врождённой аномалии или особой склонности |
| `У14` | Трансцендент | Предел понимания природы вещей, за границей человеческого восприятия |

`У11–У14` выходят за обычный человеческий диапазон и остаются ярлыками для исключительных существ: у обычных персонажей их не бывает.

## Как пользоваться

| Контекст | Правило |
| --- | --- |
| Чтение (`characters(S)`) | Документ доступен, если **хотя бы один** персонаж набора достигает порога `requires`; карта показывает **всех** (`NR-READ-02`) |
| Действие | Считается уровень **действующего** персонажа, а не максимум по группе |
| Граница в карте | «`У4`: знает до первой помощи, методику не понимает» — конкретно, а не «средний уровень» |
| `УН` | «не знает, некомпетентен»; если факт известен — «знает, не понимает» |
| Запись | Нельзя вводить факт в домене знания ниже своего уровня без решения владельца (`NR-CMP-05`) |

**Уточнение по домену важнее общей таблицы.** Если в [`schema/competence.yaml`](schema/competence.yaml) для домена знания заданы формулировки уровней, фраза «знает до …» берётся оттуда: `У4` в медицине и `У4` в политике описываются по-разному. Общая таблица — запасной вариант, когда домен ещё не размечен.

## Чего здесь нет

- **Правил доступа.** Они в [`access.md`](access.md): роль × призма, метки, `known_by`, `requires`.
- **Списка доменов знания.** Он в [`schema/competence.yaml`](schema/competence.yaml); неизвестный домен — отказ.
- **Рейтинга персонажей.** Уровни живут в `domains:` карточки, а не в отдельном файле.
