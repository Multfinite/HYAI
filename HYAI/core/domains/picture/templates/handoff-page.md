# Страница переноса (`handoff-page`)

Выходной артефакт правила `PIC-POL-10`: автономная HTML-страница, в которой **каждая пара «изображение + готовый промпт» занимает одну карточку** и копируется в другой чат двумя действиями. Прогон промптов выполняет пользователь; агент только упаковывает уже принятые изображения и уже записанные промпты.

- Каркас страницы: [`handoff-page.html`](handoff-page.html).
- Сборщик: [`build_handoff_page.py`](build_handoff_page.py).
- Процесс: [`../workflows/handoff-page.md`](../workflows/handoff-page.md).
- Политика: `PIC-POL-10`, `PIC-POL-11`, `PIC-WF-03`, `PIC-QA-07` в [`../policy.md`](../policy.md).

## 1. Входной манифест

Сборщик читает JSON-файл. Пути изображений считаются относительно каталога манифеста, если не абсолютные.

| Поле | Тип | Обязательно | Смысл |
| --- | --- | --- | --- |
| `slug` | строка | да | латиница/цифры/дефис; задаёт имена выходных файлов |
| `title` | строка | да | заголовок страницы и TXT |
| `caption` | строка | да | подзаголовок шапки |
| `note` | строка | да | доверенный HTML блока-инструкции (без пользовательского ввода и секретов) |
| `frames` | список | да | непустой; по одному элементу на пару |
| `frames[].id` | строка | да | номер/метка карточки, например `01` |
| `frames[].caption` | строка | да | подпись кадра: место, страта, состав |
| `frames[].image` | путь | да | `.png` / `.webp` / `.jpg` / `.gif`, не крупнее 10 МБ (`HYAI-ART-19`); **ровно принятый финал кадра** (`base-final` / финал владельца), не промежуточное звено |
| `frames[].image_sha256` | строка | нет | hex-`sha256` принятого финала кадра (полный 64 символа либо префикс ≥ 8); если задан — сборщик сверяет хэш встраиваемого файла и при несоответствии отказывается собирать страницу (`PIC-QA-07`) |
| `frames[].prompt_a` | строка | да | image-to-image промпт: приложить картинку + вставить текст |
| `frames[].prompt_b` | строка | нет | одиночный проход с нуля; если ни одного — переключатель A/B скрывается |
| `frames[].badge` | строка | нет | короткая метка на карточке, например `СТИЛЬ-ФИЛЬТР · ВКЛЮЧЁН` |
| `style_filter_block` | строка | нет | дословный блок стиль-фильтра владельца (`PIC-POL-08`); задаётся, если серия фильтруется |
| `require_style_filter` | булево | нет | `true` — сборщик отвергает любой промпт, который не начинается с блока `STYLE FILTER` |

Промпты берутся **как есть** из `<picture_root>/prompts/`: шаблон не дописывает, не сокращает и не меняет `negative`, веса и язык (`PIC-PRM-01..05`). Исключение — положение блока фильтра: **если для серии задан `style_filter`, каждый промпт обязан начинаться с блока `STYLE FILTER`**, а не прятать его за замком содержания. Иначе в карточке видимая часть промпта выглядит как «фильтра нет» (`PIC-POL-08`, `PIC-QA-07`). При `require_style_filter: true` сборщик проверяет это машинно и падает с указанием кадра.

```json
{
  "slug": "series",
  "title": "Серия · промпт + картинка для другого чата",
  "caption": "8 кадров · база + финальный промпт со стиль-фильтром",
  "note": "<b>Как перенести.</b> Приложите картинку и вставьте промпт текстом.",
  "style_filter_block": "rich saturated painterly finish: intensify and deepen every local color ...",
  "require_style_filter": true,
  "frames": [
    {
      "id": "01",
      "caption": "Место · страта · состав",
      "image": "frame_01.webp",
      "badge": "СТИЛЬ-ФИЛЬТР · ВКЛЮЧЁН",
      "prompt_a": "STYLE FILTER — MANDATORY, APPLY FIRST:\nrich saturated painterly finish: intensify and deepen every local color ...\n\nUse the attached image as the sole source ...",
      "prompt_b": ""
    }
  ]
}
```

## 2. Обязательная структура страницы

1. `<html lang="ru">`, HTML5, встроенные CSS и Vanilla JS, без CDN, аналитики, внешних шрифтов и сетевых запросов (`HYAI-INT-25`).
2. Шапка: заголовок, подзаголовок, переключатель `A / B` (при наличии `prompt_b`) и кнопка «Скопировать все промпты».
3. Блок-инструкция: как перенести картинку и текст в другой чат; фолбэк, если буфер картинок недоступен.
4. По одной карточке на кадр: метка `badge` (для серии с фильтром — `СТИЛЬ-ФИЛЬТР · ВКЛЮЧЁН`), изображение в `data:` URI, подпись, имя файла, неизменяемое поле с промптом, кнопки **Копировать промпт**, **Копировать картинку**, **Скачать PNG**, **Скачать исходник**, строка статуса. Блок инструкции при `require_style_filter` показывает счётчик «включён в N/N промптов».
5. `Копировать картинку` кладёт в буфер PNG полного размера (перекодировка через `canvas`); при отказе `ClipboardItem` скачивает PNG и явно сообщает об этом.
6. `Копировать промпт` имеет фолбэк `document.execCommand('copy')`; при провале просит выделить текст вручную. Никаких «тихих» успехов.
7. Контраст не ниже WCAG AA, клавиатурная навигация, адаптивная сетка.

## 3. Обязательные выходные файлы

| Файл | Что содержит |
| --- | --- |
| `<slug>-handoff.html` | страница; открывается через `present_file` |
| `<slug>-handoff.txt` | все пары «имя файла + промпт» одним текстом |
| `<slug>-handoff.zip` | `images/`, `prompts/` по одному на кадр, HTML, TXT, README |

Все три — в `<picture_root>/stages/<slug>/`, вне подмодуля HYAI (`PIC-POL-06`).

## 4. Запреты (`PIC-POL-11`)

- Никаких секретов, токенов, PII и закрытых данных: страница может попасть в скриншот (`HYAI-PERM-N02`).
- Никаких ссылок вида `sandbox:` и обещаний «кликабельного пути» в воркспейс: в чате они подчёркиваются, но не открываются. Файл открывается через `present_file`, путь сообщается обычным текстом.
- Никакой новой генерации, перезаписи изображений, выгрузки во внешние хранилища и статуса `approved` (`HYAI-PERM-N05`).
- Никаких внешних `http(s)`-ресурсов, `localStorage` с пользовательскими данными и телеметрии.
- Для серии с заданным `style_filter` (`PIC-POL-08`) промпт без блока фильтра в первой строке — брак: сборщик его отвергает, а не «тихо» выдаёт страницу.

## 5. Приёмка (`PIC-QA-07`)

Перед выдачей проверить: число карточек равно числу пар; каждой карточке соответствует ровно своё изображение и ровно свой промпт; **изображение каждой карточки — принятый финал кадра**: если зафиксирован его `sha256`, поле `image_sha256` заполнено и сборщик подтвердил сверку, контрольно расшифрованный `data:` URI даёт тот же хэш; встраивание промежуточного звена (монохромная база до раскраски `S7C`, заменённая версия) — брак; промпт не выполняет звенья конвейера (раскраска, рефрейм, добавление объектов) — неготовый финал кадра сначала доводят до приёмки (`PIC-POL-10`, `PIC-QA-07`); **каждый промпт начинается с блока `STYLE FILTER` и содержит дословный `style_filter_block`**, если для серии задан фильтр (`PIC-POL-08`); `data:` URI читаются без сети; JS синтаксически корректен (`node --check` на извлечённом скрипте); внешних `http(s)`-ресурсов, секретов и `sandbox:`-ссылок нет; ZIP распаковывается и содержит все файлы. Результат заносится в отчёт о задаче.
