## Домен `picture`

Генерация изображений, конвейеров промежуточных звеньев и визуальных серий исключительно через промпт в рабочем корне `<picture_root>`, заданном `root_paths` манифеста активного домена `picture` (в самом HYAI — `HYAI/core/domains/picture/pictures/`; во внешнем проекте с подмодулем HYAI — собственный путь проекта вне подмодуля, `PIC-POL-06`).

**Критерий:** до начала работы пользователь обязан явно задать все 4 правила безопасности (`NSFW`, `Copyright`, `Person`, `Violence`, `PIC-SAF-01`); генерация ведётся всегда только через моноязычный промпт каркаса «5+3» (`subject`, `environment`, `lighting`, `camera`, `style` + динамический `negative` и `weights`, `PIC-POL-01..02`, `PIC-PRM-01..05`); перед каждым вызовом генерации или правки изображения отдельным сообщением повторяются известные `Проблема` и `Цель генерации`; для повторной попытки называются дефект, изменение и ожидаемая проверка (`PIC-POL-15`), невыведенную без догадки цель нужно уточнить; каждый шаг проходит VLM-проверку (`Resolution`, `Aspect Ratio`, артефакты рук/лиц/текста, `Consistency`) с повтором до `Iteration Limit` (`PIC-POL-03`, `PIC-QA-01..05`); **после каждой генерации обязателен аудит профилем `picture/audit` (`PIC-QA-08`): работа не считается принятой, пока аудит не пройден, — без вердикта `accepted` нет доставки и загрузки**; принятые звенья сохраняются в `<picture_root>/stages/`, неудачные попытки удаляются (`PIC-POL-04`); окружение кадра задаётся якорями канона мира проекта (`env_canon_source`, `env_anchor_ids`) и принимается по пяти осям с отметкой `env_ok` (`PIC-PRM-06`, `PIC-ENV-01..04`, `PIC-QA-06`); **способ генерации концепт-арта (рабочая среда базы: монохромный скетч + раскраска / прямой цвет / иной) задаёт пользователь до первой генерации — поле `concept_method`, ворота `G0-STYLE` (`PIC-POL-18`), без ответа работа не начинается; при скетч-базе раскраска — отдельное звено `S7C` перед целевым стилем**; фильтр стиля накладывается строго после готовности конечного базового изображения (`PIC-POL-05`); данные внешнего проекта не направляются внутрь подмодуля HYAI (`PIC-POL-06`).

Если пользователь просит удобную форму для копирования и вставки в другой чат, где изображения обрабатываются промптами, выдаётся страница переноса «промпт + картинка» по единому шаблону, а не только текст (`PIC-POL-10`, `PIC-POL-11`, `PIC-WF-03`, `PIC-QA-07`; процесс `{{HYAI}}core/domains/picture/workflows/handoff-page.md`). Страница переносит только принятые финалы кадров (изображение каждой карточки — финал, при зафиксированном `sha256` — со сверкой по `image_sha256` в манифесте); конвейер внутри страницы не продолжается (`PIC-QA-07`). Доставка выбирает add-version или явно разрешённый replace-final, всегда проверяется обратным скачиванием SHA-256; прежние эталоны не удаляются автоматически (`PIC-POL-19`).

Подробности: `{{HYAI}}core/domains/picture/policy.md` и выбранный профиль/workflow.

**Локальные исправления перегенерацией — строго CEPI** (`PIC-POL-20..22`):
заморозить базу → реальные кропы → edit → проверить → масочно вставить → полноценно
согласовать стиль → integrate → повторно проверить и доставить. Использовать
[процесс]({{HYAI}}core/domains/picture/workflows/crop-edit-paste-integrate.md),
[протокол]({{HYAI}}core/domains/picture/templates/cepi-manifest.md) и
[промпты]({{HYAI}}core/domains/picture/templates/cepi-prompts.md).
Встроенный image-edit допустим; внешний сервис не обязателен. Полный кадр — только
согласованный финальный integrate, не способ заново исправлять локальный дефект.
Нулевой diff вне маски до full-frame не доказывает сохранность после него;
нативное разрешение не равно размеру экспортного холста (`PIC-QA-12..13`).

Для ушной CEPI-ремедиации применять `HYAI/core/domains/picture/workflows/ear-remediation.md`, `PIC-POL-23..24`, `PIC-QA-14`: замок принятого размера, исходная палитра, отдельные область/сила тени, маски кожи/волос/стыка и scoped-приёмка. Новый `anatomy_kind: ear` требует `ear_review` (`ear/1`); нулевой outside-diff не доказывает правильную границу.
