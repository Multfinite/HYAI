# `picture/audit`

Машинное описание профиля — [`profile.yaml`](profile.yaml). Общая часть наследуется из [`../../../../shared/profiles/analysis/README.md`](../../../../shared/profiles/analysis/README.md).

**Тема:** обязательный аудит каждого сгенерированного изображения сразу после генерации — попыток, звеньев, композитов и финалов (`PIC-QA-08`).
**Мыслительный процесс:** зрение на полном кадре + нативные кропы диагностических признаков, сверка с брифом и каноном, вердикт с доказательством до любой доставки.

## Чем отличается от `picture/analysis`

- `analysis` — разбор по запросу: брифов, промптов и готовых серий, без привязки к моменту генерации.
- `audit` — ворота в конвейере: срабатывает после **каждой** генерации, и его вердикт определяет, может ли работа считаться принятой. Без `accepted` нет доставки, загрузки во внешнее хранилище и статуса принятого звена.

## Что делает

1. Осматривает каждое сгенерированное изображение зрением: полный кадр уменьшенной копией (≤640 px, с фиксацией исходного `W×H`) и нативные кропы только диагностических признаков задачи (кисти/пальцы, уши/силуэт, лицо, текст/знаки, геометрия, швы композитов) — бюджет осмотра по `PIC-QA-09`.
1а. Диагностические признаки сверяет с утверждённым эталоном замерами (пропорции, углы, тон), включая бок-о-бок сравнение, **до** показа владельцу (`PIC-QA-09`); каноническая анатомия принимается по эталону, а не по текстовому описанию в промпте.
2. Сверяет результат с брифом, промптом, каноном проекта, series-anchor и осями `PIC-QA-01..07`, окружением `PIC-QA-06` и материальной эпохой, где применимо.
3. Записывает вердикт `accepted`/`rejected` с доказательством по каждой оси в журнал итераций промпта и stage-manifest.
4. При `rejected`: попытка удаляется после фиксации причины (`PIC-POL-04`), промпт точечно обновляется, генерация повторяется в пределах `Iteration Limit` (`PIC-QA-05`).
5. При обнаружении, что ранее доставленный кадр аудит не проходит, — явно возвращает его в работу и фиксирует конфликт, а не оставляет принятым.

## Чего не делает

- Не генерирует и не редактирует изображения сам: генерация остаётся за `instant`/`pipeline`, аудит только принимает или отклоняет.
- Не ставит статус `approved` (`HYAI-PERM-N05`) и не ослабляет пороги ради завершения задачи.
- Не принимает кадр «в целом хороший» при провале одной диагностической оси.
