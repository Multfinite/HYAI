# `picture/handoff-page`

Процесс реализует `PIC-POL-10` и `PIC-POL-11`: когда пользователь просит **удобную форму для копирования и вставки в другой чат**, чтобы обработать изображения промптами, агент выдаёт страницу по [`templates/handoff-page.html`](../templates/handoff-page.html), а не стену текста в чате. Процесс не генерирует изображения и не запускает прогон промптов — это делает пользователь в другом чате.

## 1. Триггер

Просьба о «форме», «удобном виде», «копировании/вставке», «переносе в другой чат», «промпт + картинка». Не путать с просьбой сгенерировать кадры: там работают [`instant.md`](instant.md), [`pipeline.md`](pipeline.md), [`series.md`](series.md). Триггер проверяется до выбора профиля генерации; пара объявляется как `picture/pipeline` (или иной активный профиль домена) по `HYAI-INT-01..04`.

## 2. Входы

| Вход | Источник | Условие |
| --- | --- | --- |
| Изображения | `<picture_root>/stages/<slug>/`, `<picture_root>/assets/` | уже принятые кадры; новые не создаются |
| Промпты | `<picture_root>/prompts/`, спецификации `prompt-spec` | готовый текст, моноязычный, с `negative` и весами; не правится |
| Подписи | карточки ассетов, матрица серии | место, страта, состав; без выдуманных фактов |
| Вариант B | промпт одиночного прохода, если есть | иначе переключатель скрывается |

Нет хотя бы одной пары «изображение + промпт» — стоп и вопрос пользователю (`HYAI-ART-06..08`).

## 3. Шаги

1. **Объявить источник и действие** перед шагом (`HYAI-INT-29`): политика `PIC-POL-10`, процесс `picture/handoff-page`, ожидаемый результат — три файла в `<picture_root>/stages/<slug>/`.
2. **Собрать манифест** по [`../templates/handoff-page.md`](../templates/handoff-page.md): по одному `frames[]` на кадр, `prompt_a` копируется дословно, `image` указывает на существующий файл. Проверить, что путей столько же, сколько промптов. **`image` каждого кадра — принятый финал кадра** (`base-final` либо финал владельца по журналу итераций спеки и `stage-manifest`), а не промежуточное звено: монохромная база до раскраски `S7C` (при `concept_method: monochrome-sketch + color-pass`) — не принятый финал, страницу не собирать, пока раскраска не сделана и не принята (`PIC-POL-18`); заменённый после ремедиации кадр — только новым файлом. Если `sha256` финала кадра зафиксирован в отчёте/журнале, записать его в `image_sha256` — сборщик отвергнет несоответствие хэша встроенного изображения. Подписи и `note` отражают финальное состояние кадра, а не его промежуточный вход. Если для серии задан `style_filter` (`PIC-POL-08`), перенести дословный блок фильтра в **первую строку каждого промпта**, задать `style_filter_block`, `require_style_filter: true` и `badge` на карточку: сборщик отвергнёт промпт, у которого фильтр спрятан за замком содержания.
3. **Отрендерить** страницу сборщиком [`../templates/build_handoff_page.py`](../templates/build_handoff_page.py): `python3 build_handoff_page.py --manifest <manifest>.json --out-dir <picture_root>/stages/<slug>/`. Сборщик встраивает изображения в `data:` URI, пишет HTML, TXT и ZIP.
4. **Проверить по `PIC-QA-07`** (раздел 5 ниже). Упавшую проверку исправить, не отключать (`HYAI-PERM-N01`).
5. **Выдать**: открыть HTML через `present_file`; в ответе по `HYAI-INT-22` перечислить все три файла таблицей «Файл · Действие · Что изменилось» и дать пути **обычным текстом в обратных кавычках**. Ссылки вида `sandbox:` не давать: в чате они только подчёркиваются и не открываются.
6. **Зафиксировать**: отчёт о задаче с `workflow: picture/handoff-page` и результатом проверки; решение `PIC-0001` при изменении самой нормы.

| Файл | Назначение |
| --- | --- |
| `<slug>-handoff.html` | страница с карточками и кнопками; основной deliverable |

## 5. Проверка (`PIC-QA-07`)

Норма списка проверок — `PIC-QA-07` в [`../policy.md`](../policy.md); ниже — её исполнительная реализация, при расхождении команд с нормой действует политика.

```bash
python3 - <<'PY'
from pathlib import Path
import re, zipfile
p = Path('<slug>-handoff.html').read_text()
print('карточек:', p.count('<section class="card"'))
print('data-URI:', p.count('data:image/'))
print('внешних http:', len(re.findall(r'(?:src|href)="https?://', p)))
print('sandbox-ссылок:', p.count('sandbox:'))
print('промптов с фильтром:', p.count('STYLE FILTER — MANDATORY'))
Path('/tmp/handoff.js').write_text(re.search(r'<script>(.*?)</script>', p, re.S).group(1))
z = zipfile.ZipFile('<slug>-handoff.zip')
print('ZIP test:', z.testzip(), '| файлов:', len(z.namelist()))
PY
node --check /tmp/handoff.js
```

Ожидается: карточек = числу пар; `data:` URI = числу пар; внешних `http` и `sandbox:` — `0`; при `require_style_filter: true` счётчик «промптов с фильтром» = числу непустых промптов во всех вариантах (A и B); `node --check` — `rc=0`; `ZIP test: None`. Дополнительно сверить вручную, что в каждой карточке лежит именно её изображение и именно её промпт и что фильтр стоит в первой строке. **Сверка финалов (`PIC-QA-07`):** если в манифесте задано `image_sha256`, сборщик уже проверил хэш каждого встраиваемого изображения при сборке (несоответствие — сбой сборки); контрольно расшифровать встроенный `data:` URI одной карточки и сверить его `sha256` с принятым финалом кадра.

## 6. Остановки и границы

- `STOP`: нет принятого изображения или промпта, конфликт путей, бинарник крупнее 10 МБ (`HYAI-ART-19`), в манифесте secrets/токены, запрос на выгрузку во внешнее хранилище без приёмки владельца; изображение кадра — не принятый финал (промежуточное звено, например монохромная база до `S7C`), либо несоответствие `image_sha256`.
- Процесс не меняет `base-final`, не накладывает `style-filter` (`PIC-POL-05`), не ставит `approved` (`HYAI-PERM-N05`), не пишет внутрь подмодуля HYAI (`PIC-POL-06`).
- Если пользователь просит «просто ссылку», а не страницу: дать путь текстом и открыть файл через `present_file`; `https://`-ссылка допустима только как отдельно согласованный статический сервер, не как замена странице.
