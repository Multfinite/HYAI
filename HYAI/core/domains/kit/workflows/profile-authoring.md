# `kit/profile-authoring`

## 1. Проверить необходимость

Профиль оправдан, если у задачи **другой мыслительный процесс** или другой артефакт. Если отличается только тема разговора — это не профиль, а формулировка задачи.

Проверка на дубль: два профиля, у которых совпадают `thought_process` и `produced_artifacts`, — дубли (`KIT-POL-08`).

## 2. Заполнить `profile.yaml`

| Поле | Обязательно | Проверка |
| --- | --- | --- |
| `topic` | да | одна строка, без «и ещё» |
| `thought_process` | да | чем отличается от соседних профилей |
| `scope_primary` / `scope_secondary` | да | пути существуют или создаются домены |
| `produced_artifacts` | да | ≥1 артефакт |
| `workflow` | да | процесс существует |
| `definition_of_done` | да | проверяемые условия, не «сделано хорошо» |
| `checklist` | да, ≥3 | вопросы, на которые профиль обязан ответить самому себе |
| `includes` | нет | общие участки из `HYAI/core/shared/profiles/` |

## 3. Написать README

Структура: тема → мыслительный процесс → зона → что делает → чего не делает → критерий готовности. Раздел «чего не делает» обязателен: он и отличает профиль от соседнего.

## 4. Не выдавать права

`KIT-POL-09`: в `profile.yaml` не должно быть `permissions`. Ограничения выражаются зоной (`scope_primary`) и объявлением `cross_scope`, а не запретом.

## 5. Проверить

```bash
python3 HYAI/tools/check_domains.py     # профиль полон, зоны не дублируются
python3 -m unittest discover -s HYAI/tools/tests  # матричный тест знает про профиль
```

Матричный тест обязан включать новый профиль: профиль без теста — объявление о несуществующей возможности (`rc=1`).
