# Сохранение результата

## Что куда

| Результат | Куда | Почему туда |
| --- | --- | --- |
| решение с обоснованием | файловая память, затем граф | читаемо и переживает сессию |
| подтверждённый факт | граф, с источником | нужна история изменений |
| корпус документов | семантический индекс | нужен поиск по смыслу |
| изменение кода | репозиторий и коммит | единственный источник истины |
| диаграмма | файл источника в проекте | иначе теряется вместе с сервисом |
| крупный артефакт | облачное хранилище | репозиторий не резиновый |
| заметка для человека | личное хранилище заметок | читается вне проекта |

## Порядок

1. Репозиторий: изменения кода и документов зафиксированы.
2. Файловая память: решение, итог, следующий шаг.
3. Граф: только подтверждённые факты, с источником и датой.
4. Семантический индекс: документы целиком, не пересказ.
5. Проверка: прочитать сохранённое и убедиться, что оно на месте.

Обратный порядок опасен: индекс и граф могут ответить, а открыть будет нечего.

## Что не сохраняется

- Секреты, ключи, токены, пароли — нигде.
- Персональные данные и содержимое чужих файлов.
- Черновики рассуждений и промежуточные варианты.
- Догадки: гипотеза становится записью только после проверки.

## Идемпотентность

Перед записью — поиск существующей записи. Повторный прогон не должен создавать дубли: либо
обновление по тому же ключу, либо пропуск, если запись уже верна.

## Проект

Ключ проекта задаётся во всех системах памяти одинаково. Запись без ключа уходит в общий набор и
смешивает проекты; исправить это задним числом нельзя — только переписать.

## Ошибки

- Запись в граф без источника: факт есть, проверить нечем.
- Перезапись файла без чтения: потеря предыдущих решений.
- Сохранение пересказа вместо документа: поиск теряет точные формулировки.
- Сохранение «на всякий случай» всего подряд: шум вытесняет нужное при следующем поиске.

## Без серверов

Отчёт в репозитории и файлы решений. Явно скажи, что часть памяти не сохранена.
