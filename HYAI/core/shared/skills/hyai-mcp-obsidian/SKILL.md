# obsidian — заметки хранилища

## Что даёт

Доступ к заметкам хранилища: поиск, чтение, создание, правка. Всё остаётся обычными файлами с
разметкой и связями, которые человек видит в своём приложении.

## Когда брать

- знания проекта ведутся заметками, а не базой;
- нужен человекочитаемый след с обратными ссылками;
- правка, которую сразу увидит владелец хранилища.

Не брать: массовая запись фактов из задачи — для этого есть файловая память; хранение секретов.

## Порядок

1. Поиск заметки по заголовку или тексту.
2. Чтение целиком: свойства в заголовке файла — часть данных.
3. Правка минимальным диффом, сохраняя существующие связи и метки.
4. Проверка: перечитать заметку и убедиться, что связи не порваны.

## Ловушки

- Правка видна владельцу сразу: черновики и сомнительные формулировки туда не пишутся.
- Переименование заметки рвёт входящие ссылки, если их не обновить.
- Свойства во frontmatter должны сохранять тип: строка, список, дата.
- Доступ требует ключа; без него сервер неработоспособен.

## Без сервера

Файлы хранилища читаются и правятся как обычные Markdown-файлы.

## Проверка

Заметка открывается, ссылки ведут на существующие заметки.
