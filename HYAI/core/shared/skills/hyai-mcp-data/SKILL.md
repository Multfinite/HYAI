# Данные: несколько хранилищ

## Участники и что у каждого

| Сервер | Модель | Сильная сторона | Не для |
| --- | --- | --- | --- |
| dbhub | таблицы, SQL | точные выборки, агрегаты | обход связей |
| neo4j | граф, Cypher | связи и пути | табличные отчёты |
| qdrant | векторы | сходство с фильтром | точные значения |
| vectorstore | индекс файлов | поиск по смыслу | транзакции |
| gdrive | файлы | обмен артефактами | запросы |

## Что меняется от комбинации

- Одно хранилище — вопрос решается одним запросом.
- Добавили второе — появляются два ответа на один вопрос и риск «джойна» между ними.
- Добавили векторный индекс — появляется приблизительный ответ без гарантии полноты.

## Главное ограничение

Хранилища не связаны между собой. Соединение данных — это два запроса и сопоставление в ответе,
с явной оговоркой, что связи между ними не проверены хранилищем.

## Порядок

1. Понять, в каком хранилище вообще лежат данные: схема, список коллекций, каталог.
2. Чтение с лимитом: только нужные колонки или поля, ограниченное число строк.
3. Проверить полноту: не обрезан ли ответ лимитом.
4. Изменение — только по подтверждению, с указанием, что именно изменится.
5. Проверка — повторное чтение изменённого.

## Ошибки комбинации

- Перенос строк из одного хранилища в другое без явной задачи.
- Агрегат по неполной выборке.
- Сравнение данных из разных источников без указания, что это разные источники.
- Запрос без лимита, который вытесняет из контекста всё остальное.

## Персональные данные и секреты

Не выгружаются в ответ, в память и в отчёт. Если без них задача не решается, нужен явный ответ
пользователя и минимальный объём.

## Без хранилищ

Работа с выгрузками и файлами: попроси дамп или таблицу, дальше — обычная обработка.
