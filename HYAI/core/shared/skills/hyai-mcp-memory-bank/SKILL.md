# memory-bank — память проекта в файлах

## Что даёт

Проект — каталог, заметка — файл. Данные читаемы человеком и живут дольше любой сессии.

## Когда брать

- перед задачей: правила проекта, предыдущие решения, прогресс;
- после задачи: записать решение, итог, следующий шаг;
- нужен след, который прочитает другая сессия или другой агент.

## Порядок

1. Список проектов — убедиться, что нужный проект существует и имя свободно.
2. Список файлов проекта, затем чтение тех, что нужны: правила владельца, решения, прогресс.
3. Правка: прочитать файл, слить старое с новым, записать целиком.
4. Проверка — перечитать файл и убедиться, что предыдущее содержимое не потеряно.

## Ловушки

- Создание и перезапись — разные операции: создание падает, если файл есть, перезапись падает,
  если файла нет. Поэтому порядок всегда «прочитать → слить → записать».
- Запись поверх нечитанного файла теряет данные без возможности восстановления.
- Имя проекта обязательно во всех вызовах: без него вызов не пройдёт.
- Секреты, ключи и пароли в память не пишутся — только ссылка на место хранения.

## Соглашения по файлам

| Файл | Содержимое | Как менять |
| --- | --- | --- |
| `project.md` | что за проект, цель, границы | перезапись целиком |
| `owner_rules.md` | правила владельца, запреты, стиль | дополнять |
| `decisions.md` | решения с обоснованием и датой | только дописывать |
| `progress.md` | текущее состояние и следующие шаги | перезаписывать |
| `task_<id>.md` | активная задача | свернуть до итога после завершения |

## Без сервера

Заметки в файлах репозитория: `decisions.md`, `progress.md`, отчёт о работе. Часть контекста
теряется, но данные остаются в проекте.

## Проверка

Прочитанный после записи файл содержит и старое, и новое.
