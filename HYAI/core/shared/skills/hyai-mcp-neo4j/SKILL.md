# neo4j — граф через Cypher

## Что даёт

Запросы к графу: обход связей любой глубины, агрегаты по узлам. Естественная модель для
зависимостей и связей, которые в таблицах пришлось бы собирать джойнами.

## Когда брать

- вопрос «кто с кем связан» и «сколько шагов между»;
- хранение и обход сетевых данных проекта;
- проверка целостности связей.

Не брать: табличные отчёты, полнотекстовый поиск, хранение документов.

## Порядок

1. Схема: какие метки узлов, типы связей и свойства существуют.
2. Чтение: запрос с явным `LIMIT`, сначала узкий, потом расширять.
3. Проверка: вернуть идентификаторы и свойства, которые нужны для следующего шага.
4. Запись: только с явными параметрами и подтверждением пользователя, если данные общие.

## Ловушки

- Запрос без `LIMIT` вытаскивает весь граф и переполняет контекст.
- Запись меняет общие данные; удаление узла снимает связи безвозвратно.
- Метки и типы связей чувствительны к регистру и опечаткам.
- Параметры вместо склейки строк: склейка ломается на кавычках и открывает инъекцию.

## Без сервера

Данные в файлах или в реляционной базе; обход связей — вручную несколькими запросами.

## Проверка

Запрос возвращает ровно ожидаемое число строк, а изменяющий запрос — подтверждённый результат.
