# Память проекта: несколько хранилищ

## Участники и что у каждого

| Сервер | Роль | Сильная сторона | Слабость |
| --- | --- | --- | --- |
| memory-bank | файлы заметок проекта | читаемо человеком, долговечно | нет поиска по смыслу |
| graphiti | факты и связи | время действия, история | нет документов, отложенная обработка |
| cognee | поиск по корпусу | находит по смыслу | индекс отстаёт |
| qdrant | векторная коллекция | фильтры по полям | наполняется вручную |
| vectorstore | индекс каталога | не требует подготовки | устаревает после правок |
| obsidian | личные заметки | видит человек | не канон проекта |
| serena (memories) | заметки внутри проекта | рядом с кодом | видны только этому инструменту |

## Что меняется от комбинации

- Один сервер памяти — источник истины очевиден.
- Добавили граф — появляется время: два разных факта могут быть оба верны в своих периодах.
- Добавили семантический поиск — поиск стал лучше, доверие к найденному ниже: индекс отстаёт.
- Добавили векторный индекс — появился второй, конкурирующий индекс; ответы могут расходиться.
- Добавили заметки — появился человекочитаемый слой, который не является каноном.

## Иерархия истины

1. Пользователь в текущей сессии.
2. Файлы памяти проекта: правила владельца, решения.
3. Документы репозитория: политики, решения, спецификации.
4. Факты графа — с интервалами действия.
5. Семантический поиск — подсказка, где искать.
6. Векторные индексы — навигация, не истина.
7. Заметки в личном хранилище — мнение, не норма.

Правило: ответ семантического или векторного поиска проверяется по файлу или документу до того,
как на него опираются.

## Порядок чтения

1. Файлы памяти: правила, решения, прогресс.
2. Документы репозитория по теме.
3. Граф: что менялось и когда.
4. Семантический поиск — если предыдущее не дало ответа.

## Порядок записи

1. Файлы памяти: прочитать, слить, записать целиком.
2. Граф: короткий эпизод с источником и датой.
3. Семантический индекс: ингест документа целиком, а не пересказа.
4. Векторный индекс — если он вообще используется в проекте.

Обратный порядок создаёт знание, которого нет в источнике: индекс отвечает, файла нет.

## Один проект — один ключ

| Система | Параметр | Если не задать |
| --- | --- | --- |
| memory-bank | проект | вызов не пройдёт |
| cognee | набор и раздел | запись уйдёт в общий набор |
| graphiti | группа | поиск не увидит проектные данные |
| qdrant | поле проекта в нагрузке | данные смешаются |

Переименование ключа у существующих записей разрывает историю: перенос проекта — это новый ключ
и повторная запись, а не правка параметра.

## Ошибки комбинации

- Записали в граф, но не в файлы: следующая сессия увидит факт без источника.
- Записали в индекс, не записав в файлы: поиск нашёл, открыть нечего.
- Записали в файлы, но забыли индекс: поиск не находит, хотя данные есть — это не потеря.
- Два противоречащих факта без интервалов: граф покажет оба, разбирайся по источникам.

## Удаление

Удаление в графе и в семантическом индексе необратимо и требует явного указания пользователя.
В файловой памяти эквивалент — перезапись без нужного фрагмента, и её можно отменить только из
истории репозитория, если файлы версионируются.

## Без серверов памяти

Файлы проекта и отчёт о работе. Явно скажи, что память не сохранена вне репозитория.
