# cognee — поиск по смыслу

## Что даёт

Принимает документы, хранит их по наборам и отвечает на вопросы по смыслу, а не по совпадению
слов. Дополнительно умеет строить граф знаний по загруженному корпусу.

## Когда брать

- вопрос «что мы уже решили про…» по большому корпусу;
- поиск фрагмента, точной формулировки которого не помнишь;
- сохранить набор документов проекта для последующих вопросов.

Не брать: точные факты с датами — это темпоральная память; поиск по коду — это символьные
инструменты.

## Порядок

1. Набор документов (`dataset`) задавать всегда: без него запись уходит в общий набор и проекты
   смешиваются.
2. Раздел внутри проекта (`node_set`) — тег вроде «decisions», «specs», «ops»: по нему потом
   фильтруется выборка.
3. Ингест документа, затем построение связей, если оно нужно для вопросов по связям.
4. Поиск: вопрос своими словами, `top_k` небольшой, ссылки на источники включать.
5. Проверка: найденный ответ сверить с исходным документом.

## Ловушки

- Индекс отстаёт от источника: ответ — подсказка, где искать, а не истина.
- Повторный ингест того же документа создаёт дубли, если не проверять набор заранее.
- Очистка памяти необратима и требует явного указания.
- Секреты не ингестятся: корпус читают все, у кого есть доступ к набору.

## Без сервера

Поиск по репозиторию текстовыми средствами и чтение найденных файлов. Медленнее, но точнее:
источник виден целиком.

## Проверка

Ответ найден вместе с источником, и источник открывается.
