# dbhub — реляционная база

## Что даёт

Подключение к базе и выполнение SQL: схема, выборки, изменения. Один инструмент на разные СУБД.

## Когда брать

- нужны реальные данные, а не выгрузка в файле;
- нужно понять схему и связи таблиц;
- нужно проверить гипотезу о данных запросом.

Не брать: хранение заметок, поиск по коду, обход связей графа.

## Порядок

1. Список подключений — выбрать нужное, не угадывать.
2. Схема: таблицы, колонки, типы, ключи.
3. Чтение: `SELECT` с явным `LIMIT` и только нужными колонками.
4. Изменение: сначала показать запрос и ожидаемое число строк, затем выполнять по подтверждению.
5. Проверка: повторное чтение изменённых строк.

## Ловушки

- `DDL`/`DML` меняют общие данные: без подтверждения пользователя — нельзя.
- Права учётной записи ограничивают доступ: отказ базы — ответ, а не повод обходить.
- Часовые пояса и типы дат искажают сравнения, если их не учитывать.
- Персональные данные не выгружаются в ответ и не попадают в память.

## Без сервера

Запрос у пользователя: дамп, выгрузка или скриншот схемы. Дальше — работа с файлом.

## Проверка

Выборка содержит ожидаемые строки; после изменения данные читаются в новом виде.
