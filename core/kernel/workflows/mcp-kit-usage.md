# Работа агента со стеком multfinite-mcp-kit (standard workflow)

**Домен:** `software`, **профиль:** `software/architect` (или другой, по задаче) `[И]`.
**Источник правил:** `HYAI/AGENTS.md` §1, §3a, §6, §7 `[И]`.
**Источник стека:** `multfinite-mcp-kit/README.md`, `docs/independent-installation.md`, `common/registration-manifest.mjs` `[И]`.

## WF-MCP-00. Проверка mcp-kit при старте (отдельный пункт входа)

Перед любым первым действием в задаче агент **обязан** выполнить этот пункт:

1. **Уточнить у пользователя:** выдан ли ему URL MetaMCP и API-ключ, и есть ли доступ к mcp-kit (GLOBAL, LOCAL, дополнительные endpoints). Если не выдан — работа со стеком невозможна, агент действует без MCP-инструментов.
2. **Проверить доступные MCP:** используя выданный URL MetaMCP и ключ, запросить список зарегистрированных серверов/endpoints. Уточнить, какие из них стандартные (из кита), а какие дополнительные (выданы сверх стандартных).
3. **Зафиксировать для себя:** записать в рабочую память агента список доступных endpoints и их серверы (код, память, последовательное мышление, веб, граф и т.д.). Эта фиксация — основа для всего дальнейшего процесса.
4. **Только потом** приступать к планированию и выполнению задачи.

**Врата:** без выполнения WF-MCP-00 работа со стеком не начинается. `[А]`

## Категории доступных серверов и когда их использовать `[И]`

| Категория | Серверы (из `registration-manifest.mjs`) | Зачем использовать |
|-----------|------------------------------------------|-------------------|
| **Последовательное мышление** | `sequentialthinking` | Разбивать задачу на шаги, проверять промежуточные выводы, не терять нить рассуждений. Использовать на każом не trivial шаге. |
| **Память (графовая)** | `graphiti`, `cognee`, `memory-bank-mcp` | Хранить и извлекать контекст задачи, соединения между фактами, предыдущие решения, ошибки и паттерны. Перед началом — спросить память; после завершения шага — сохранить инсайт. |
| **Анализ графа кода** | `codegraph`, `codebase-memory-mcp`, `serena` | Понимать структуру проекта, зависимости, где что менялось. Перед кодовыми изменениями — обязательно проверить граф. |
| **Код и файлы** | `filesystem-mcp`, `git`, `mcp-everything-search`, `DesktopCommanderMCP` (Windows) / `universal-computer-control` (Linux) | Читать/писать файлы, коммитить, искать по репозиторию, управлять терминалом и рабочим столом. |
| **Веб и исследование** | `fetch`, `duckduckgo-mcp-server`, `context7`, `playwright-mcp` | Искать информацию, читать документацию, брать контекст из интернета. |
| **Векторный поиск и БД** | `mcp-server-qdrant`, `mcp-neo4j-cypher`, `dbhub` | Семантический поиск по памяти, запросы к графам и базам. |

**Вложенность (global → local):** один endpoint может отдавать сразу несколько серверов (`MCPKIT_ENFORCE_SINGLE_SERVER_PER_ENDPOINT=false` по умолчанию). Глобальный MetaMCP может вести на локальные серверы на другой машине. Агент не должен различать, где физически сервер — он просто вызывает нужный инструмент по имени endpoint. Но LOCAL-серверы (`filesystem-mcp`, `git`, `serena` и т.д.) работают с файловой системой текущей машины, а GLOBAL-серверы — с общими сервисами за шлюзом. `[И]`

## WF-MCP-01. Планирование с использованием MCP

После WF-MCP-00 агент составляет план задачи с обязательным использованием `sequentialthinking`:

1. Разбить цель на шаги.
2. Для каждого шага указать: какой MCP-сервер (из зафиксированного списка) используется, какой инструмент, какой ожидается результат.
3. Проверить промежуточные выводы перед переходом к следующему шагу.
4. Если в процессе появляются новые факты — корректировать план через `sequentialthinking`.

**Правило:** не делать крупных действий без промежуточной проверки через память и мышление. `[А]`

---

## WF-MCP-02. Сбор контекста перед выполнением

Перед первым кодовым или действийым шагом:

1. **Память:** запросить из `graphiti` / `cognee` / `memory-bank-mcp` всё, что связано с задачей (предыдущие решения, ошибки, паттерны). Не начинать с чистого листа, если контекст уже сохранён.
2. **Код:** через `codegraph`, `serena`, `codebase-memory-mcp` понять структуру проекта, где нужные файлы, какие зависимости.
3. **Файлы:** через `filesystem-mcp` и `mcp-everything-search` найти нужные файлы.
4. **Веб:** при необходимости — `fetch`, `duckduckgo-mcp-server`, `context7`.

**Выход:** полная картина контекста, зафиксированная в рабочей памяти. `[В]`

---

## WF-MCP-03. Выполнение с использованием MCP

Выполнять шаги плана, используя подходящие серверы из зафиксированного списка:

- Кодовые изменения — `filesystem-mcp`, `git`, `serena`.
- Поиск по коду — `codegraph`, `mcp-everything-search`.
- Терминал/рабочий стол — `DesktopCommanderMCP` / `universal-computer-control`.
- Внешние запросы — `fetch`, `playwright-mcp`, `duckduckgo-mcp-server`.
- Векторный поиск — `mcp-server-qdrant`, `mcp-neo4j-cypher`.

Каждое действие — с проверкой результата перед переходом к следующему. `[В]`

---

## WF-MCP-04. Сохранение в память (обязательно после каждого шага и в конце)

После завершения каждого значимого шага и в конце задачи:

1. Сохранить ключевые решения, ошибки, паттерны в `graphiti` / `cognee` / `memory-bank-mcp`.
2. Связать новые факты с существующими (графовая память).
3. Отметить, какие дополнительные endpoints оказались полезны, для будущих задач.

**Цель:** следующее решение той же или похожей задачи должно идти быстрее, потому что агент «помнит» контекст. `[А]`

---

## WF-MCP-05. Проверка и отчёт

1. Проверить, что цель достигнута.
2. Проверить, что данные не потеряны, тесты и линтеры не ослаблены (HYAI-PERM-N01).
3. Составить отчёт: что сделано, какие MCP-серверы использованы, что сохранено в памяти, какие проблемы остались.
