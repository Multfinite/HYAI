# Индекс правил домена

Полный текст — [`policy.md`](../../../../HYAI/core/domains/software/policy.md).

| Правило | Начало |
| --- | --- |
| `SW-POL-01` | Порядок доверия: принятое решение (HYAI/meta/decisions/software/) → контракт (схема, тип, публичный интерфейс) → тест → реализация → комментарий → документация. |
| `SW-POL-02` | Расхождение кода и контракта — дефект кода, а не повод поправить контракт «по факту». |
| `SW-POL-03` | Сначала проверка, потом код: тест, воспроизведение, бенчмарк. |
| `SW-POL-04` | Существующий тест не ослабляется (HYAI-PERM-N01): удаление, skip, сужение ассерта требуют решения и одобрения. |
| `SW-POL-05` | Баг сначала воспроизводится падающим тестом, потом исправляется. |
| `SW-POL-06` | Рефакторинг не меняет поведение. |
| `SW-POL-07` | Новая зависимость — только с обоснованием: что даёт, чем заменить, что будет при её удалении (HYAI-PERM-G03). |
| `SW-POL-08` | Слои не нарушаются: домен не импортирует инфраструктуру, инфраструктура не содержит бизнес-правил. |
| `SW-POL-09` | Глобальное состояние и скрытые синглтоны — запрещены, кроме явно объявленных в архитектуре. |
| `SW-POL-10` | Ошибка не проглатывается: либо обрабатывается осознанно, либо пробрасывается с контекстом. |
| `SW-POL-11` | Сообщение об ошибке содержит, что произошло, где и что делать. |
| `SW-POL-12` | Документация описывает контракт, а не реализацию. |
| `SW-POL-13` | Ссылка из документации на код — с путём и, где полезно, строкой (../src/auth.py#L42); такая ссылка проверяется check_links.py. |
