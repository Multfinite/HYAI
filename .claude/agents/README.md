# Агенты команды

Два блока ролей: ПО-команда и литературно-сценарное направление.

## ПО-команда

| Агент | Роль |
| --- | --- |
| `Coordinator` | координация цепочки, декомпозиция цели, контроль результата |
| `Developer` | реализация по спецификациям Архитектора и UX-дизайнера |
| `Designer UI-UX` | интерфейс и пользовательский опыт |
| `Sofrware Engineer` | инженерная реализация (историческое имя файла) |
| `Bug Fixer` | локализация и исправление дефектов |
| `Quality Engineer` | тестирование и приёмка качества |
| `Reviewer` | ревью кода, безопасности и поддерживаемости |
| `Domain Specialist` | предметное исследование и проверка фактов |
| `Web Seeker` | поиск и проверка внешних источников |
| `Technical Writer` | API Reference, руководства, ADR, README, инструкции |

## Литературно-сценарное направление

| Агент | Роль |
| --- | --- |
| `Screenwriter` | структура и драматизм: фабула, поэпизодник, арки, темп |
| `Worldbuilder` | логика вселенной: законы мира, история, география, системы |
| `Novelist` | фактура и текст: атмосфера, сенсорика, ритм, стиль |
| `Dialogue Specialist` | голоса персонажей: лексикон, подтекст, речевые привычки |
| `Literary Editor` | финальная вычитка: стиль, логика, целостность |

## Пайплайн литературной команды

1. **Координатор / Главред** задаёт концепцию книги или сценария.
2. **Лор-мастер** создаёт правила мира; **Архитектор сюжета** делает поэпизодник.
3. **Автор-прозаик** пишет текст глав на основе поэпизодника.
4. **Диалогист** дорабатывает разговорные сцены или пишет их параллельно.
5. **Литературный редактор** принимает работу, вычитывает стиль и логику и выдаёт готовый продукт.

## Формат агента

Каждый файл `.md` содержит три раздела:

- **Goal** — цель и зона ответственности;
- **Backstory** — роль и рабочий процесс;
- **Taste & Judgments** — критерии качества и границы.
